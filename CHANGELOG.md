# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.7.0] - Unreleased

The second Fluent UI v9 parity release: Phase 2 of the [roadmap](docs/ROADMAP.md), menus and commands, plus the presence core that new surfaces mount through from now on. It closes 3 high, 9 medium and 17 low gaps of the [Fluent UI v9 comparison](docs/research/fluent-ui-v9-comparison.md) (the ids in backticks below). Fluent's names are used where they fit Wave's conventions (`checkedValues`, `persistOnItemClick`, `openOnHover`, `openOnContext`, `isAccessible`, `Menu.ItemCheckbox`, `Toolbar.RadioGroup`); a state callback is named after its state and receives the value first, with extra data in a second, optional `details` argument (`onCheckedValuesChange(checkedValues, details?)`, Fluent's `onCheckedValueChange(event, data)`). **Nothing public was removed**, and no public type was narrowed. Changes of behaviour, DOM structure and types that are not additions are listed under [Changed](#changed): read them before upgrading if your tests assert Wave's DOM or console output, or hover over menu items.

### Upgrading from 0.6

1. **Menu surfaces mount through the presence core.** Every `Menu.Popover` surface renders `data-presence` (`"entered"` while open) next to its `data-state="open"`. While an exit motion of yours runs, it stays mounted with `data-state="closed"`, `data-presence="exiting"` and `inert`. Without exit classes a menu still unmounts at once: before the browser paints, in the same `act()` as the close. Assertions on the surface's exact attributes change.
2. **Menu columns.** Every menu item with a label renders a hidden, `aria-hidden` placeholder span before its label for each column it does not fill (the check column, the icon column), and a menu that mixes items with and without icons (or checks) now lines their labels up. Assertions on an item's children or markup change; its text and accessible name do not.
3. **Toolbar** renders `data-size` and `data-orientation`, and `Toolbar` has static parts (`Toolbar.Button`, …). Assertions on the root's exact attributes, and type checks of `keyof ToolbarOwnProps`, change.
4. **ToggleButton with a `role`.** With `role` `checkbox`, `radio`, `switch`, `menuitemcheckbox`, `menuitemradio`, `option` or `treeitem` it renders `aria-checked` and `data-checked` instead of `aria-pressed`; with any other role (`tab`, `link`, `menuitem`, …) it renders neither and warns once in development. Every pressed ToggleButton renders `data-pressed`. A test finds a pressed `role="checkbox"` toggle with `getByRole('checkbox', { checked: true })`, not `{ pressed: true }`.
5. **Tooltip `delay`** is deprecated: use `openDelay`. The old prop still works and warns once in development, which a test that spies on `console.warn` sees.
6. **`Menu.Item` `persistOnClick`** defaults to the Menu's new `persistOnItemClick`, which is `false` unless you set it: 0.6 menus behave as before.
7. **Focus follows the mouse in menus.** While focus is in a menu (an open popup menu and its submenus, or a static menu the user is in), the enabled item under the mouse pointer takes focus, as in Fluent and native menus. Tests that hover an item and then press Enter or an arrow key act on the hovered item. Keyboard use is unchanged, and hover never takes focus into a menu that focus is not in.
8. **Class merging (tailwind-merge 3.7).** Wave now requires `tailwind-merge` `^3.7.0`. With it, `cn`, which merges every component's `className`, lets an axis shorthand of yours (`px-*`, `mx-*`, `inset-x-*`, `border-x-*`, and the `y` forms) replace a component's own logical side class of the same variant (`ps`/`pe`, `ms`/`me`, `start`/`end`, `border-s`/`border-e`, and the block sides). 0.6 kept both, and the component's side class won in the CSS. `<Dialog.Title className="px-6">` now drops its `pe-8`, so a long title can run under the Close button: write `px-6 pe-8` to keep the side, or set only the side you mean (`ps-6`). See [Behaviour](#behaviour).
9. **Node.js 22.12 or later.** `engines.node` is `>=22.12.0` (was `>=20.19.0`): Node.js 20 has been end-of-life since 2026-04-30. On an older Node.js, npm and pnpm only warn (`EBADENGINE`) unless `engine-strict` is set, and Yarn 1 refuses to install. See [Packaging](#packaging).

### Added

- **Shared types**, public through the package entry: `CheckedValues` (`Readonly<Record<string, readonly string[]>>`, checked items per group `name`), `CheckedValuesChangeDetails` (`{ name, checkedItems, event }`), `CheckedValuesChangeHandler`, `PopupRect`, `VirtualElement` (`{ getBoundingClientRect(): PopupRect; contextElement?: Element }`, a positioning anchor that is not an element, such as a point) and `PopupTarget` (`HTMLElement | VirtualElement | null`).
- **Motion tokens**, with the values of Fluent's `motionTokens`, on `:root` in every style entry: eight durations, `--wave-duration-ultra-fast` (50ms), `-faster` (100ms), `-fast` (150ms), `-normal` (200ms), `-gentle` (250ms), `-slow` (300ms), `-slower` (400ms) and `-ultra-slow` (500ms), and nine curves, `--wave-curve-accelerate-max`, `-accelerate-mid`, `-accelerate-min`, `-decelerate-max`, `-decelerate-mid`, `-decelerate-min`, `-easy-ease-max`, `-easy-ease` and `-linear`. They are the same in every theme and are not zeroed under reduced motion (components reduce their own motion). On the Tailwind path they are the utilities `duration-wave-*` and `ease-wave-*` (`duration-wave-normal ease-wave-decelerate-mid`), and `cn` merges them with Tailwind's `duration-*` and `ease-*`; the precompiled `./styles` holds the variables only, as it holds only the utilities Wave itself uses. The guide's motion chapter now lists these values (five of the 0.6 reference curves were wrong). Closes `foundation-16`.
- **Presence core**: `usePresence(visible, options?)` and the `<Presence visible>` component mount and unmount an element with CSS enter and exit motion, without a JS animation library or inline styles. The element carries `data-presence` with its phase (`PresencePhase`: `entering`, `entered`, `exiting`, `exited`): style its enter with Tailwind's `starting:` variant gated on the entering phase (`data-[presence=entering]:starting:…`; an ungated `starting:` also animates an element that mounts `entered`) and its exit with `data-[presence=exiting]:` classes. While it exits it stays mounted and `inert` (out of the tab order and the accessibility tree); a phase ends when the element's own animations and transitions have finished, and at once without motion or under `prefers-reduced-motion: reduce`. The server HTML renders the `entered` (or `exited`) phase, and `appear` runs the enter motion only for an element mounted on the client after hydration. `unmountOnExit={false}` keeps an exited element mounted, `hidden` and `inert`, so its state survives; `onEntered` and `onExited` report the end of a phase. Types `PresencePhase`, `PresenceAttributes`, `UsePresenceOptions`, `UsePresenceResult` and `PresenceProps`. Every `Menu.Popover` mounts through it (see [Changed](#changed)); an import of only `Button` contains none of it. Closes `foundation-14`.
- **Menu**:
  - **Checkable items**: `Menu.ItemCheckbox`, `Menu.ItemRadio` and `Menu.ItemSwitch` (`MenuItemSelectableProps`: required `name` and `value`), bound by `name` and `value` to the Menu's new `checkedValues`, `defaultCheckedValues` and `onCheckedValuesChange(checkedValues, details?)`. A checkbox, switch or radio item is checked while its `value` is in `checkedValues[name]`; checking a radio item makes its value the group's only value, so give a radio group at most one value. Any string is a group name, `constructor` and `__proto__` included. The callback fires only on change and receives a new object whose arrays are copies (so `onCheckedValuesChange={setState}` works), then `details`: `{ name, checkedItems, event }`, the group that changed, its new values and the item's click. The items render `role="menuitemcheckbox"` (checkbox, switch) or `"menuitemradio"` with `aria-checked`, and `data-checked` while checked. **Space** changes the state and keeps the menu open; **Enter** and a click change it and close a popup menu (the APG menu pattern). Activating a radio item whose value already is its group's only value changes nothing and still closes the menu. A `name` and `value` pair is unique within a menu list (a second item with the same pair warns in development, since both would show as checked). A check glyph shows while a checkbox or radio item is checked; `checkmark` replaces it, and since a checked item always shows an indicator, a `checkmark` that renders nothing keeps the glyph (with a development warning). The switch item draws a decorative switch at the end of its row. They work in static and popup menus alike: `checkedValues` does not make a Menu a popup menu. A static menu renders the checked state in the server HTML. Closes `menu-11`, `menu-12`, `menu-13`.
  - **`persistOnItemClick`** keeps a popup menu open after any of its items is activated; an item's own `persistOnClick` (`true` or `false`) wins.
  - **Column alignment**: once any item of a menu list shows a check or an icon, every item of that list keeps that column, so the labels line up, through groups and wrapper elements too. It is CSS (`:has()`), with no props and no second render. Closes `menu-6`.
  - **`Menu.Group` and `Menu.GroupHeader`**: `role="group"`, labelled by its header when the header is a direct child (or inside a Fragment, also one written in a Server Component); a header nested deeper does not label it (development warning), and `aria-label` names a group without a visible header (a consumer `aria-label` or `aria-labelledby` wins when it is defined; one that holds `undefined`, from a wrapper that forwards it, does not). Give a group one header: only the first header among its direct children labels it, and any other header (a second one, or one inside your own component) renders only its own `id` and warns in development. Arrow keys and typeahead skip headers, whose text lines up with the item labels. Give the radio items of each `name` their own group, or at least separate two sets with `Menu.Divider`: assistive technology counts a radio set by its group or separators, not by `name`. Closes `menu-15`.
  - **`Menu.ItemLink`**, polymorphic (default `'a'`; `as` takes a router link component that forwards `ref` and spreads its props onto the anchor): `role="menuitem"` on the link. Enter is the browser's own link activation (Shift, Ctrl and Cmd open a new window or tab), Space follows the link too, and every click follows it and closes a popup menu, a Ctrl- or Cmd-click included; `persistOnItemClick` does not keep it open. Middle click and the link's context menu stay native and close nothing. A disabled link is `aria-disabled` and its click is prevented; an element link (`'a'`) also drops its `href`, while a router link keeps what its own `to` renders. Closes `menu-14`.
  - **Submenus**: a `<Menu>` rendered in a menu list (inside `Menu.Popover`, or among the items of a static menu) is a submenu. Its `Menu.Trigger` wraps a `Menu.Item`, which becomes its trigger item: `aria-haspopup="menu"`, `aria-expanded`, `aria-controls` while open, `data-has-submenu` and a chevron that mirrors in RTL. ArrowRight (ArrowLeft in RTL), Enter, Space and a click open the submenu and focus its first item; ArrowLeft (ArrowRight in RTL) and Escape close only that submenu and return focus to its item; item activation and Tab close every level and put focus on the root trigger first (under a static menu, on the submenu's trigger item). One submenu of a list is open at a time, and a closing menu closes its open submenu first, so a controlled submenu gets `onOpenChange(false)` once. A submenu opens on the `end` side (`Menu.Popover` defaults to `side="end"` and `offset={0}` there) and flips to fit the viewport; with room on neither side (a wide menu, a phone) it is shifted over its parent menu, inside the viewport, as native and Fluent menus do. It shares its parent's checked values unless it sets `checkedValues` or `defaultCheckedValues` (an `onCheckedValuesChange` alone only listens: it is called after the parent's), and inherits `persistOnItemClick`, `openDelay` and `closeDelay` unless it sets them. A Menu inside a Popover or Dialog opened from an item stays a root menu of its own. Closes `menu-10`.
  - **`Menu.SplitGroup`**: one row with an action item and the button of a submenu, written as a `Menu.Item` without children and with an `aria-label` inside the submenu's `Menu.Trigger` (it shows only the chevron). ArrowDown and ArrowUp visit both halves; ArrowRight (ArrowLeft in RTL) moves from the action to the submenu button, and on the button opens the submenu. It works in static menus too. Closes `menu-16`.
  - **Hover opening**: `openOnHover` (default `false` on a root menu, `true` on a submenu), `openDelay` and `closeDelay` (250ms each; mouse hover only; a static menu passes them on to its submenus). A menu opened by hover takes no focus; a click, Enter, Space or ArrowDown on its trigger keeps it open and moves focus into it, as opening it that way does. A hover opening that a controlled menu applies later (in a transition) is still one. It closes `closeDelay` after the pointer has left the trigger and the menu, unless focus is inside it (focus on the trigger does not count). A close by hover moves no focus, and neither does the close of a submenu that goes with it; every other close returns focus as before. A triangle between the trigger and the menu keeps it open while the pointer moves diagonally into it; meanwhile the sibling items it crosses neither open their submenus nor take focus. After Escape or an outside press it does not reopen until the pointer has left the trigger. Touch and pen never open anything by hover, and an `aria-disabled` trigger never opens. `openOnHover` is ignored with `openOnContext` and on a static menu (development warnings). Closes `menu-2`, `foundation-22`, `positioning-8`.
  - **Context menus**: `openOnContext` makes `Menu.Trigger` a context-menu region (a list, a row, a canvas). A right click (a Ctrl+click on macOS, a long press where the browser fires `contextmenu`) opens the menu at the pointer, and Shift+F10 or the ContextMenu key at the focused element inside the region; focus moves to the first item and returns, on Escape or item activation, to the element that had it at the gesture (Tab closes the menu, and tabbing continues from that element). A menu your app opens without a gesture (a controlled `open`) forgets the last gesture's element. A second gesture on another row moves the open menu there without closing it (no `onOpenChange` call). The browser's context menu is suppressed on the region and inside the menu, except in text fields inside the region, which keep it (paste, spelling suggestions) and open nothing. A primary press elsewhere (on another row too), a right click outside, or a scroll that moves the region or the row of the gesture (the row under the pointer, which a scroll of the region's own content moves, or the focused row) closes the menu. The region gets no `aria-haspopup`, `aria-expanded` or `aria-controls`, since it is no menu button (a render-prop child that spreads them has them removed, with a development warning), so name the menu with `aria-label` on `Menu.Popover` (a development warning asks for one), and consider `aria-keyshortcuts="Shift+F10"` on the region. Known limitation: iOS Safari fires no `contextmenu` on a long press, so there is no touch gesture there. Closes `menu-1`.
  - **`Menu.Popover` `target`** (`PopupTarget`): an element held in state, or a `VirtualElement` (an inline object is fine), to place the menu at instead of next to `Menu.Trigger`; a controlled menu with a `target` needs no trigger (name it with `aria-label`). A press on a target element is no outside press, so a toggle button used as the target closes the menu with one click; it carries its own `aria-haspopup="menu"` and `aria-expanded`. Closes `positioning-2`, and `foundation-18` with Popover.
  - Flat names for Server Components: `MenuItemCheckbox`, `MenuItemRadio`, `MenuItemSwitch`, `MenuItemLink`, `MenuGroup`, `MenuGroupHeader` and `MenuSplitGroup`, with the types `MenuItemSelectableProps`, `MenuItemCheckboxProps`, `MenuItemRadioProps`, `MenuItemSwitchProps`, `MenuItemLinkProps`, `MenuItemLinkOwnProps`, `MenuGroupProps`, `MenuGroupHeaderProps` and `MenuSplitGroupProps`.
- **Popover**:
  - **Hover cards**: `openOnHover`, `openDelay` (250ms) and `closeDelay` (500ms, Fluent's `mouseLeaveDelay`), mouse hover only. A popover opened by hover takes no focus, and a close by hover moves none (nor does the close of a hover card opened inside it); a click on its trigger keeps it open and keeps focus where it is (a second click closes it, as without hover). It closes `closeDelay` after the pointer has left the trigger and the content, unless focus is inside the content or a layer opened from it; focus on the trigger does not keep it open. The safe zone, the dismissal rule and the touch rule are Menu's. The content keeps its 0.6 place in the Tab order (after the trigger) and its name. Closes `popover-1`, and `foundation-22` with Menu.
  - **Context popovers**: `openOnContext`, as on Menu. A right click opens the popover at the pointer and leaves focus where it is (Tab from that element enters the content); Shift+F10 or the ContextMenu key opens it at the focused element and moves focus into the content (its first tabbable element, else the surface); Escape returns focus to that element. Name the content with `title`, `aria-label` or `aria-labelledby` (development warning otherwise). Closes `popover-2`.
  - **`target`** on the Popover root, next to `side` and `align` (`PopupTarget`, as on `Menu.Popover`): a controlled popover with a `target` needs no trigger, a press on a target element is no outside press, and Tab from the target element enters the content when there is no trigger. A toggle button used as the target carries its own `aria-haspopup="dialog"`, `aria-expanded` and `aria-controls` (give `Popover.Content` an `id`). Closes `popover-3`, and `foundation-18` with Menu.
  - **Note on `target`**: on Menu and Popover it takes an element or a `VirtualElement` but no ref in 0.7, while TeachingPopover's `target` takes an element or a ref but no `VirtualElement`. Both are to be unified, without breaking either (ROADMAP P7-01).
- **Tooltip** `openDelay` (default 200ms, Fluent's `showDelay`), which applies on hover and on keyboard focus as the 0.6 `delay` did, and `closeDelay` (default 100ms, the 0.6 timing, Fluent's `hideDelay`) after the pointer has left the child and the tooltip; blur and Escape still hide it at once. `delay` is deprecated (see [Deprecated](#deprecated)). Closes `tooltip-3`.
- **Toolbar**:
  - `size` (default `'medium'`): the default size of its button parts and the toolbar's padding (`p-0.5` at the two small sizes, `p-1`, `p-1.5`, `p-2`); plain Buttons inside keep their own default. Closes `buttons-20`.
  - `checkedValues`, `defaultCheckedValues` and `onCheckedValuesChange(checkedValues, details?)`, with Menu's semantics, for the parts below; the pressed and checked states are in the server HTML. A `name` and `value` pair is unique within a toolbar (a second part with the same pair warns in development). Closes `buttons-19`.
  - `Toolbar.Button`: a Button with the toolbar's size and the `subtle` appearance by default (yours win), polymorphic like Button; `vertical` puts the icon (in a 24px box, 20px at the two small sizes) above a caption-size label, for ribbons. Closes `buttons-24`.
  - `Toolbar.ToggleButton`: a ToggleButton with the same defaults and required `name` and `value`, pressed while `value` is in `checkedValues[name]`; a click adds or removes it (your `onClick` runs first, and `preventDefault()` cancels the change). A plain ToggleButton inside a Toolbar is not bound to `checkedValues`. Closes `buttons-25`.
  - `Toolbar.RadioGroup` and `Toolbar.RadioButton`: `role="radiogroup"` (always; a `role` you pass is ignored) around `role="radio"` toggles, one checked value per `name`. The radios are part of the toolbar's arrow-key order, and Up and Down (Left and Right in a vertical toolbar, mirrored in RTL) also move among the group's radios, wrapping inside it. The arrow keys never check a radio; Space, Enter or a click does, and a click on a radio whose value already is its group's only value changes nothing. A group without `aria-label` or `aria-labelledby` warns in development. Closes `buttons-26`.
  - `Toolbar.Group`: lays out related controls in the toolbar's direction; `role="presentation"`, or `role="group"` when you name it (a `role` you pass wins). Closes `buttons-27`.
  - `Toolbar.Divider`: a `role="separator"` line across the toolbar with the opposite `aria-orientation`; it is not focusable, so the arrow keys pass it. Closes `buttons-28`.
  - Flat names for Server Components: `ToolbarButton`, `ToolbarToggleButton`, `ToolbarRadioGroup`, `ToolbarRadioButton`, `ToolbarGroup` and `ToolbarDivider`, with the types `ToolbarButtonProps`, `ToolbarButtonOwnProps`, `ToolbarToggleButtonProps`, `ToolbarRadioButtonProps`, `ToolbarRadioGroupProps`, `ToolbarGroupProps` and `ToolbarDividerProps`.
- **ToggleButton** `isAccessible` (Fluent's name): the pressed state as a brand fill with on-brand text (on `primary`, the pressed fill with an inset on-brand stroke), so it never depends on a light tint. Recommended for icon-only toggles in toolbars; forced colors are unchanged. Closes `buttons-8`. A `role` now decides which state attribute it renders (see [Changed](#changed)). Closes `buttons-10`.
- **`useRovingTabIndex`**: an element marked `data-roving-transparent` is never a nested composite, whatever its role, so its items join the enclosing arrow-key order (`Toolbar.RadioGroup` uses it); it must not carry `data-roving-container`. When the marker goes away, the items get their own `tabindex` back.

### Changed

#### Behaviour

- **Menu: focus follows the mouse.** While focus is inside a menu tree (an open popup menu and its submenus, or a static menu with focus in it; not a Popover, Dialog or other portal opened from an item, which keeps focus), the mouse moving over an enabled item focuses that item (without scrolling), except while a submenu's safe zone holds the pointer. A submenu that loses focus to the pointer this way closes `closeDelay` later, not at once (at once with `openOnHover={false}`), and hovering it again keeps it; a keyboard move to another item still closes it at once. Hover never takes focus from outside the menu, so a hover-opened menu, or a static menu the user is not in, leaves focus where it is. As in Fluent and native menus: with focus left behind, Enter would activate an item the user is not pointing at.
- **Menu surfaces on the presence core**: every `Menu.Popover`, root and submenu, mounts through `usePresence`. Its dismiss layer, focus return and positioning still follow the open state, so on close focus returns and the next Escape reaches the layer below at once, not after an exit motion, and a trigger activated during the exit reopens the same surface. Without exit classes the surface unmounts before the browser paints and in the same `act()` as in 0.6, in a second render of the closing commit (code that reads the DOM in a layout effect of that commit sees the `inert` surface).
- **`Menu.Item` `persistOnClick`** defaults to the Menu's `persistOnItemClick` (`false` unless set), so 0.6 menus behave as before.
- **ToggleButton** reports its state for its role, read from the first token of `role`: `aria-pressed` without a `role` or with `role="button"` (as in 0.6); `aria-checked`, and `data-checked` while pressed, with `role` `checkbox`, `radio`, `switch`, `menuitemcheckbox`, `menuitemradio`, `option` or `treeitem` (a consumer `aria-pressed` is dropped); neither with any other role (`tab`, `link`, `menuitem`, …), with a one-time development warning. 0.6 rendered `aria-pressed`, which ARIA allows only on buttons. `onPressedChange` is unchanged.
- **Tooltip** `delay` warns once in development: it is the deprecated name of `openDelay`.
- **Class merging**: Wave requires `tailwind-merge` 3.7 (see [Packaging](#packaging)). With it, `cn`, which merges every component's `className`, lets a later axis shorthand replace the logical side classes it covers, of the same variant: `px-*` replaces `ps-*` and `pe-*`, `mx-*` replaces `ms-*` and `me-*`, `inset-x-*` replaces `start-*` and `end-*`, `border-x-*` replaces `border-s-*` and `border-e-*`, and the `y` forms replace the block sides. 0.6 kept both classes, and since Tailwind writes the side utilities after the shorthand, the component's side class won. `<Dialog.Title className="px-6">` had 32px of end padding (its `pe-8`, the room for the Close button) and now has 24px; `className="px-6 pe-8"` keeps the 32px, and `ps-6` changes only the start side. A later side class of yours still stays next to an earlier shorthand (`cn('px-4', 'ps-3')` keeps both), and a class of another variant is kept (`hover:pe-2` stays next to `px-4`). An app that already installed tailwind-merge 3.7 through the earlier `^3.5.0` range has this behaviour already.

#### Visual

- **Menu columns**: when any item of a menu list shows an icon or a check, every item of that list reserves the icon or check column, so the labels line up. A 0.6 menu that mixes items with and without icons now indents the items without one; one without icons looks as before.
- **Toolbar** padding follows `size`; the default `medium` keeps the 0.6 padding.
- The menu item whose submenu is open keeps its hover background (in forced colors, a start bar that is not the focus ring).

#### DOM structure

- Every `Menu.Popover` surface carries `data-presence` (`entering`, `entered`, `exiting`); while an exit motion runs it keeps `data-state="closed"` and `inert`. Every menu list (the static `role="menu"` element and every `Menu.Popover` surface) has the class `group/menu`.
- Every menu item with a label renders an `aria-hidden` column placeholder before its label for each column it does not fill (`<span data-menu-column-space="checkmark">` without a check column, `"icon"` without an icon), hidden unless the list shows that column; the icon box carries `data-menu-icon`. Checkbox and radio items render a `data-menu-checkmark` column (checked or not), and all three checkable items render `data-checked` while checked; `Menu.ItemSwitch` renders an `aria-hidden` `data-menu-switch` span, a submenu trigger item `data-has-submenu` and a chevron, and `Menu.SplitGroup` `data-menu-split-group`. An item's shortcut renders `dir="auto"` (see [Fixed](#fixed)).
- ToggleButton renders `data-pressed` while pressed, and `data-checked` while pressed with a checked role (so on a checked `Toolbar.RadioButton` too).
- Toolbar always renders `data-size` and `data-orientation`; a vertical `Toolbar.Button` renders `data-vertical`, `Toolbar.Group` `data-orientation`, and `Toolbar.RadioGroup` `data-roving-transparent`.
- In context mode (`openOnContext`) a Menu or Popover trigger element has no `aria-haspopup`, `aria-expanded` or `aria-controls`; a Popover opened by a keyboard context gesture has `tabindex="-1"` on its surface.
- As in 0.6, enumerated attributes are always present with their value (`data-presence`, `data-size`, `data-orientation`) and boolean ones are present (`""`) or absent (`data-checked`, `data-pressed`, `data-has-submenu`, `data-vertical`).

#### Types

- `MenuTriggerProps` gains the optional members `onPointerEnter`, `onPointerMove`, `onPointerLeave` and `onContextMenu`; nothing is narrowed (`aria-expanded` is still `boolean`). A render-prop child receives the pointer handlers in every mode (they act only while hover opening is on); in context mode it receives `onContextMenu`, `aria-expanded={false}` and no `aria-controls`. `PopoverTriggerChildProps` is unchanged: its optional handler members are now filled in hover and context modes.
- `MenuItemProps.children` is optional (only for the submenu half of a `Menu.SplitGroup`, which then needs `aria-label`), and `MenuItemProps.persistOnClick` documents its new default.
- `typeof Toolbar` gains static members (`Toolbar.Button`, …), and `ToolbarOwnProps` gains `size`, `checkedValues`, `defaultCheckedValues` and `onCheckedValuesChange`: a `keyof ToolbarOwnProps` check in your code sees them.
- `MenuProps`, `MenuPopoverProps`, `PopoverProps`, `TooltipProps` and `ToggleButtonProps` gain the optional props listed under [Added](#added).

#### Packaging

- **Node.js**: `engines.node` `>=20.19.0` → `>=22.12.0`, since Node.js 20 is end-of-life. 22.12 is the first Node.js 22 release that enables `require()` of ES modules by default and marks import attributes stable, and the Node.js 22 floor of Vite 8. The built files use neither: the ESM and CommonJS entries load and render on the server on Node.js 22.12.0.
- **Runtime dependencies**: `tailwind-merge` `^3.5.0` → `^3.7.0`, which changes how `cn` merges an axis shorthand with the logical sides (see [Behaviour](#behaviour)), and `@floating-ui/react-dom` `^2.1.6` → `^2.1.9`. `clsx` and the peer dependencies are unchanged.

## [0.6.0] - Unreleased

The first Fluent UI v9 parity release: Phase 1 of the [roadmap](docs/ROADMAP.md), small changes that need no new subsystem. It closes 34 medium and 14 low gaps of the [Fluent UI v9 comparison](docs/research/fluent-ui-v9-comparison.md) (the ids in backticks below, such as `buttons-3`, are its gap ids) and mitigates two more (`badge-1`, `taggroup-1`). Fluent's prop names are used where they fit Wave's conventions (`disabledFocusable`, `iconPosition`, `validationState`, `modalType`, `selectTabOnFocus`); open state keeps Wave's `open`/`defaultOpen`/`onOpenChange`, and extra callback data goes in a second, optional `details` argument. **Nothing public was removed**, and no public type was narrowed except the `color` attribute that ProgressBar and CounterBadge inherit (see [Types](#types-1)). Changes of behaviour, DOM structure and types that are not additions are listed under [Changed](#changed-1): read them before upgrading if your tests assert Wave's DOM or callback arguments, or your CSS styles Wave's internals.

### Upgrading from 0.5

1. **Dialog and Drawer `onOpenChange`** receive a second argument, `details` (`{ reason, event }`). Handlers and code that calls the prop keep compiling, but exact test assertions change: `expect(onOpenChange).toHaveBeenCalledWith(false)` becomes `toHaveBeenCalledWith(false, expect.anything())`, or `expect.objectContaining({ reason: 'escape' })` to check the reason.
2. **Field** keeps its hint visible below a validation message, and error messages show an icon (`validationMessageIcon={null}` removes it). The message text now sits in a `<span>` after the `aria-hidden` icon: assertions on the message's markup change, assertions on its text or on the control's accessible description do not.
3. **Anchors without `href`** (`<Link onClick>`, `<Link as="span">`, `<Button as="a">` without `href`) are buttons now: `role="button"`, a tab stop and Enter/Space activation. A disabled `<a>` without `href` has `role="button"` too (was `link`), and so does a disabled `Link as="span"` (it had no role); a disabled one is still neither a tab stop nor activated. Tests that found them with `getByRole('link')` use `getByRole('button')`.
4. **A disabled Link** no longer lets its click reach ancestor `onClick` handlers, or Enter and Space through, as a disabled Button already did.
5. **TimePicker** keeps rejected typed text on blur, marks the input `aria-invalid` and shows an error message, instead of reverting the text; Enter, and leaving the input with edited text, close the list whether the text is committed or kept.
6. **Combobox and TimePicker** show a chevron button by default (`expandIcon={false}` hides it), and Combobox and Dropdown wrap their control in a new `<div>`: tests that count buttons or expect the control to be the root's direct child change.
7. **`ToastController`** has a new member, `dismissAllToasts`: test doubles and other code that implements the interface add it.
8. **RatingDisplay** formats its accessible name with the runtime locale when `locale` is omitted, rounded to one decimal. Pass `locale` when rendering on the server.
9. **Badge `color="important"`** keeps its orange look through 0.x, but becomes Fluent's neutral high-emphasis color in 1.0: use `color="severe"` for orange (see [Deprecated](#deprecated-1)).

### Changed

#### Behaviour

- **Field**: the hint stays visible below a validation message and renders after it (0.5 hid it while an error showed); both describe the control, message first. Error messages show an icon (`validationMessageIcon={null}` restores the 0.5 look). A development warning fires when `error` hides a `validationMessage` or a non-error `validationState`. Changing `orientation` on a mounted Field remounts the control (the horizontal layout wraps it), so an uncontrolled control loses its state and focus.
- **`useFieldControl`** describes a control with the Field's validation message in any state (`validationMessageId`, else `errorId`), then the hint; `aria-invalid` still comes only from the error state. The ColorPicker hex input is described by a warning, success or neutral Field message too (0.5: only by an error).
- **Anchors without `href`**: a `Link` without `href`, a Link with a non-interactive `as` (`span`, `div`) and `Button as="a"` without `href` get `role="button"`, a tab stop and Enter (key down) / Space (key up) activation; your `role` and `tabIndex` win. Any `href` string, `''` included, keeps link semantics. Closes `buttons-15`, `buttons-5`.
- **A disabled Link** stops its click from reaching ancestor `onClick` handlers and blocks Enter and Space (0.5 only prevented the click's default). A disabled Link or `Button as="a"` without `href` has `role="button"` (was `link`), and so does a disabled `Link as="span"` (it had no role); with an `href` it keeps `role="link"`.
- **Menu**: a `Menu.Popover` taller than the space next to its trigger is limited to the available height and width and scrolls inside the viewport, and the item focused on opening is scrolled into view. A `max-h-*` or `max-w-*` class on `Menu.Popover` replaces the limit, and so does a `style`. Closes `menu-3`. `Menu.Trigger` ignores a click, Enter, Space, ArrowDown and ArrowUp from an `aria-disabled="true"` element at or inside the trigger (the child itself, or the element inside a wrapper span; an `aria-disabled` ancestor outside the trigger does not count) and leaves the event's default alone, so a `disabledFocusable` MenuButton or SplitButton menu half never opens its menu. This also applies to a trigger you mark `aria-disabled="true"` yourself.
- **Checkbox and Switch** send a consumer `aria-disabled` to the control button (0.5 left it on the root `<label>`); without `disabledFocusable` it still only sets the attribute.
- **Checkbox, Switch and `RadioGroup.Item`** warn in development about `children` that render content: they were dropped silently in 0.5 and are still not rendered (pass the label in `label`).
- **SplitButton** warns in development about a `menuIcon` that renders nothing, and keeps the chevron.
- **TimePicker**: rejected typed text (not a time, or outside `minTime`/`maxTime`) is kept on blur instead of reverted, marked `aria-invalid` and described by an error message (`role="alert"`; left to a surrounding Field that shows an error), and reported through `onInvalidInput`. Enter that rejects text keeps it too. Enter and leaving the input close the list whether they commit or keep the text, so the list does not cover the message. The flag clears when the text is edited, an option is picked, the clear button or Escape replaces the text, the form resets, the parent passes a new value, or the picker becomes disabled or read-only.
- **RatingDisplay**: the accessible name formats the value with `locale`, or with the runtime default locale when `locale` is omitted, rounded to one decimal: `4.65` is named "Rating: 4.7 out of 5", and "Rating: 4,5 out of 5" in a German runtime. A RatingDisplay rendered on the server without `locale` can therefore mismatch on hydration when the server's default locale differs from the browser's: pass `locale`.
- **ProgressBar** inside a `Field` is named by the Field's label when it has no name of its own (and then no longer logs the missing-name warning), described by the Field's message and hint, and colored by its validation state. `aria-invalid` and `aria-required` are never rendered on the bar (neither is allowed on `role="progressbar"`), also when you pass them outside a Field.
- **Badge and CounterBadge** with an `aria-label` or `aria-labelledby` that is neither empty nor whitespace only get `role="img"`, so the name is announced (a `role` you pass wins). A whitespace-only name, such as a missing translation, adds no role.
- **Dialog and Drawer**: a backdrop press that closes the surface still moves focus to `<body>` first, as in 0.5, so the focused control's blur runs before the surface closes (a SpinButton's or picker's typed value is committed, as with the Close button). When the press does not close the surface, focus ends up where it was: an alert dialog's backdrop does not move focus at all, and a controlled dialog or drawer that refuses `outside-press` gives focus back to the field the press blurred, unless your handler moved focus elsewhere.
- **Toaster**: a toast's timer starts when the toast shows, not when it is dispatched (no difference without `limit`).
- **Spinner**: the one-frame announcement deferral starts when the spinner shows (after `delay`). An `appearance` outside the union (from untyped code) renders as `primary`.
- **Slider** always attaches its own `onChange` (composed with yours, which runs first) to keep the fill in step, so React no longer warns about a controlled `value` without `onChange`.

- **Nav**: a collapsed category that contains the current page shows the selected look (while hovered, the toggle's hover background shows under it).
- **Field**: warning and success messages have their own colors, and every message state except `none` has an icon.
- **Checkbox, Switch and `RadioGroup.Item`**: the box, track or radio lines up with the first line of a label that wraps or has a second line, instead of being centred on the whole label. The roots are `items-start`, and a labelled box or radio sits 1px down to centre on the 20px first line. Pass `className="items-center"` to centre the indicator on a tall label again.
- **Focus rings of unavailable controls** keep full contrast: a control dimmed to 50% by the disabled look goes back to full opacity while it shows its keyboard focus ring (the opacity dimmed the ring too, to about 2.2:1). This covers `disabledFocusable` on the button family, Link, Checkbox and Switch, a Button with your `aria-disabled="true"`, the Pagination, Carousel and DatePicker month buttons that disable themselves and keep focus, the DatePicker's unavailable calendar days (they stay focusable in the grid), and any other control with the library's `aria-disabled` look that takes keyboard focus. On Checkbox, Switch, `RadioGroup.Item`, SearchBox and an Input with `contentBefore` or `contentAfter`, any focus ring inside the dimmed root lifts it (also a focused link in the label of a disabled Checkbox, Switch or radio, and a focusable clear button or slot content in a disabled SearchBox or Input). While the ring shows, the control looks enabled; `aria-disabled` and the not-allowed cursor still mark it as unavailable.
- **MessageBar, SearchBox and Tag**: the dismiss and clear buttons show the disabled look (`cursor-not-allowed`, 50% opacity) while `aria-disabled="true"`: a merged `disabledFocusable` Button, or your own `aria-disabled` on a merged `<button>`.

#### DOM structure

- CompoundButton wraps its text lines in a `<span data-wave-compound-content>`, which now holds the `flex-col items-start` column; the root is `items-center justify-start gap-3`. Without any text it renders as an icon-only Button.
- Combobox wraps its `<input>` in a `<div class="relative flex items-center">` with the clear and expand buttons. Dropdown wraps its `<button role="combobox">` the same way, followed by the clear button, and its chevron is absolutely positioned inside the combobox button. TimePicker renders one more `<button>` (the chevron) and, while its text is flagged, an error `<p>`.
- Field messages: the text sits in a `<span>` after an `aria-hidden` icon span, and the `<p>` carries `data-validation-state`. A non-error message has the id `<fieldId>-message`; the error message keeps `<fieldId>-error`.
- Disabled Buttons (every button-family member) and disabled Links render `data-disabled=""`; `disabledFocusable` adds `data-disabled-focusable=""`.
- New state attributes. Enumerated ones are always present, with the resolved value: `data-validation-state` and `data-orientation` (Field), `data-label-position` (Checkbox, Switch), `data-color` and `data-appearance` (Badge, CounterBadge), `data-color` (ProgressBar), `data-appearance` and `data-state` (Spinner), `data-modal-type` (`Dialog.Content`). Boolean ones are present (`""`) or absent: `data-dot` (CounterBadge), `data-compact` (RatingDisplay), `data-contains-current` (the Nav category toggle), `data-disabled-focusable`.
- A ProgressBar that is a Field's first child receives the Field's control id as its `id`, as every first child does. Nested in a Field's wrapper element it gets an id of its own (`progress-…`) and never takes the control id; outside a Field it renders no `id` (as in 0.5).
- The `Menu.Popover` surface carries the classes `max-h-(--wave-popup-available-height)` and `max-w-(--wave-popup-available-width)` (no inline `max-height` or `max-width`), so a `max-h-*` or `max-w-*` class in `className` still limits the menu, as in 0.5, and an inline `style` wins over both. The Dialog body carries the `--wave-dialog-footer-height` variable while a footer is measured.

#### Types

- `label` of Checkbox, Switch and `RadioGroup.Item` is `React.ReactNode` (was `string`).
- `CounterBadgeProps.count` is optional.
- `BadgeColor` adds `'severe'` and `'subtle'`: an exhaustive `switch` or a `Record<BadgeColor, …>` in your code needs the two new members.
- `ToastController` has a new member, `dismissAllToasts`: code that implements the interface (test doubles) must add it.
- `FieldContextValue` has two new optional members, `validationState` and `validationMessageId`.
- `onOpenChange` of Dialog and Drawer has a second, optional parameter, `details`. A `(open) => void` handler and code that calls the prop with one argument keep compiling; test assertions on the exact arguments need the second one: `toHaveBeenCalledWith(false)` becomes `toHaveBeenCalledWith(false, expect.anything())`.
- `ProgressBarProps.color` is `ProgressBarColor`: it narrows the `color?: string` inherited from `React.HTMLAttributes` (the presentational HTML attribute, which does nothing on a `<div>`).
- `CounterBadgeProps.color` is `BadgeColor`: it narrows the `color?: string` that 0.5 inherited from `React.HTMLAttributes` (CounterBadge had no `color` prop of its own). A string outside the palette from untyped code renders as `brand`.
- `ButtonOwnProps`, `CompoundButtonOwnProps` and `LinkOwnProps` have new keys (`iconPosition`, `disabledFocusable`, `icon`), which `keyof` checks in your code see; `SplitButtonMenuButtonProps` gains `disabledFocusable`.
- `focusableDisabledProps` (internal) takes an optional second argument.

### Deprecated

- **Badge `color="important"`** keeps its orange (severe) look through 0.x, as in 0.5, and becomes Fluent's neutral high-emphasis color (near black in the light theme) in 1.0. Use `color="severe"` to keep the orange look. There is no development warning in 0.6: the last 0.x minor adds one. CounterBadge's `important` follows Badge.
- **Notice:** the `details` parameter of the Dialog and Drawer `onOpenChange` becomes required in 1.0. Read it as `details?.reason` until then; handlers written that way keep compiling.

### Fixed

- **Tag stories**: `FilterGroup` and `Dismissible` no longer drop keyboard focus on `<body>` after a dismissal. They follow the "Focus after dismissal" recipe of Tag's documentation (focus the next tag's dismiss button, else the previous one, else a nearby button, before removing the tag). Mitigates `taggroup-1` until TagGroup ships.
- **Field** renders a `label`, `hint` or `error` given as a generator; the presence check consumed it and it rendered empty.
- **Right-to-left mirroring in apps built with Vite, and in the built Storybook.** Vite 8's default CSS minifier (Lightning CSS, for targets below Chrome 120) rewrote the `:dir(rtl)` of the `wave-rtl:` variant to a `:lang(ar)`, `:lang(he)`, … list, so a page that sets `dir="rtl"` without a right-to-left `lang` got no mirroring: the checked Switch thumb sat outside its track, the Slider fill ran from the wrong edge, and the chevrons (Breadcrumb, Pagination, Tree, DatePicker, PresenceBadge), the Select arrow and the indeterminate ProgressBar animation were not mirrored. This affected the precompiled `./styles` and the `./tailwind` path since 0.5. The variant now selects by `:nth-child(n of :dir(rtl))`, which matches the same elements and which Lightning CSS, esbuild, cssnano and clean-css keep as written. Apps that import `./variants.css` in a custom setup get the fix without a change. Browsers without `:dir()` (Chrome and Edge 111–119) keep the `[dir=rtl]` fallback. The README's "Global effects" covers your own `:dir()` rules and postcss-preset-env.
- **TimePicker and DatePicker** with `clearable`: Tab from erased text clears the value before focus moves, so focus goes on to the next tab stop (DatePicker's calendar button; for TimePicker, the tab stop after the picker). The clear button, until then the next tab stop, disappeared with the value that the Tab cleared, and focus dropped to `<body>`.
- **TimePicker**: leaving the input with edited text closes the list, and Tab closes a list that shows only a status text ("No matching times", "No times available"). The list used to stay open while focus moved to the clear button, showing every option again after a typed time was committed.
- **MenuButton** `menuIcon` no longer nests a `<button>` or `Button` passed to it (or a slot object whose `as` is one) inside the button, which was invalid HTML and caused a hydration error: its children become the glyph (the chevron when they render nothing), its props are dropped, and a one-time development warning names the slot.

## [0.5.0] - Unreleased

The full-review release: it addresses the 305 issues found by a review of the whole library (accessibility, theming, packaging, forms, overlays, keyboard support and tests), and the issues found by a second full-codebase review of that work (compounds written in React Server Components, keyboard and focus order, forms, forced colors, localizable built-in labels, right-to-left styling inside mixed-direction pages, types and tooling). One is a partial won't-fix: Wave's Tailwind color utility names (`bg-primary`, `text-foreground`, …) stay unprefixed in 0.5, and namespacing them is being considered for 1.0; see the README's "Global effects" for the colliding names and workarounds. **Nothing public was removed.** Renamed props and values keep their 0.4 names as deprecated aliases that warn once in development and will be removed in 1.0. Changes of behaviour, DOM structure and types that are not renames are listed under [Changed](#changed-2); read them before upgrading if you style Wave's internals or assert its DOM in tests.

### Upgrading from 0.4

1. **Package name.** The npm package has always been `@mortenbrudvik/waveui` (0.4.0 was published under that name), so an npm dependency needs no change. Before 0.5 the repository's `package.json` used the name `waveui`, and the 0.4 guide showed `import { WaveProvider } from 'waveui'`: replace such imports, and a git or local dependency named `waveui`, with `@mortenbrudvik/waveui` (`import { Button } from '@mortenbrudvik/waveui'`).
2. **Styles.** Pick one path:
   - Without Tailwind: keep `import '@mortenbrudvik/waveui/styles'`. It is now precompiled CSS and needs no Tailwind. Make sure every Wave tree is inside a `WaveProvider`: the base styles and the reset of native elements are scoped to it.
   - With Tailwind 4: replace the `./styles` import with `@import 'tailwindcss'; @import '@mortenbrudvik/waveui/tailwind';` in your CSS entry. Never import `./styles` as well.
   - With Tailwind 4 and a prefixed build (such as `prefix(tw)`): import `./styles` instead of `./tailwind`, in your CSS entry and into a cascade layer between Tailwind's `base` and `utilities`: `@layer theme, base, wave, components, utilities; @import 'tailwindcss' prefix(tw); @import '@mortenbrudvik/waveui/styles.css' layer(wave);`. Imported unlayered, Wave's base styles override your utilities inside `WaveProvider`. See the README's "Global effects".
   - 0.4 applied Tailwind's Preflight and `body` styles (Segoe font, 14px, theme colors) to the whole page. If markup outside `WaveProvider` relied on them, import `@mortenbrudvik/waveui/preflight.css` and style `body` yourself.
3. **CSS variables.** Rename overrides of the 0.4 semantic variables (`--primary`, `--primary-foreground`, `--background`, `--foreground`, `--card`, `--secondary`, `--muted`, `--muted-foreground`, `--accent`, `--destructive`, `--border`, `--input`, `--ring`, `--subtle`, `--success`, `--warning`, `--error`, `--info`, `--severe`, …) to their `--wave-*` names. App CSS that **reads** 0.4 variables must switch to the `--wave-*` names as well: `var(--primary)`, `var(--ring)` (the 0.4 guide showed `outline: 2px solid var(--ring)`), and also the ramp names `var(--brand-*)` and `var(--grey-*)`, which 0.5 reads only as fallbacks and never defines. Until then, `import '@mortenbrudvik/waveui/legacy-tokens.css'` after the Wave styles defines the 0.4 names again (deprecated). Overrides of the 0.4 ramp names (`--brand-*`, `--grey-*`) keep working without any change; reads of them do not.
4. **Tailwind theme values.** 0.4 redefined Tailwind's `--radius-sm` … `--radius-3xl` and `--font-sans` for your whole app. Your own `rounded-sm`, `rounded-md`, `rounded-lg`, `rounded-xl`, `rounded-2xl` and `rounded-3xl` classes now get Tailwind's default sizes (4, 6, 8, 12, 16 and 24px instead of 2, 4, 6, 8, 12 and 16px), and `font-sans` is Tailwind's stack again; use `font-wave` for Wave's font. Wave's own components look the same (they now use the Tailwind names that match their 0.4 sizes).
5. **Theme classes.** In your own CSS target `.wave-light`, `.wave-dark` and `.wave-high-contrast`; `.dark` and `.high-contrast` still work but are deprecated.
6. **Deprecated props.** Replace them using the [migration table](#migration-table). Each warns once in development. Mind the "fires" column: the new value callbacks fire only on change.
7. **Required fields.** A required `Field` now turns on the browser's constraint validation for the control inside it, not only `aria-required`: native inputs and the library Input, Select, Textarea, Slider, SpinButton and SearchBox while empty, and the choice and picker controls (Checkbox, Switch, RadioGroup, Rating, SwatchPicker, ColorPicker, Combobox, Dropdown, TagPicker, DatePicker, TimePicker) until they are checked, switched on or have a value, also without `name`. `<Field required><Switch /></Field>` therefore blocks the submit while the switch is off. Forms that validate in their submit handler add `noValidate` to the `<form>`.
8. **Tests and custom styles.** Triggers no longer render a wrapper `<span>`, popups render in portals (query them with `screen`), boundary buttons use `aria-disabled`, composite controls put `id` and their naming and validation `aria-*` attributes on their focusable element, PresenceBadge is `role="img"` (was `role="status"`), and the AvatarGroup overflow is a button. Mirrored glyphs use Wave's `wave-rtl:` variant instead of `rtl:` (a custom Tailwind setup built on `./tokens` imports `./variants.css` for it), SearchBox draws its field on its root `<div>`, and Combobox and TagPicker announce "No matches" through a hidden status element (the visible row is `aria-hidden`). See [Changed](#changed-2).
9. **Nested providers.** A nested `WaveProvider` inherits `theme`, `dir` and `portalContainer` from the enclosing one when it omits them. Pass `dir="ltr"` to a nested provider that must stay left-to-right inside an RTL app, and `portalContainer={null}` to send its overlays to `document.body`.

### Migration table

`onChange` is now reserved for the native DOM change event. Value callbacks are `on<Thing>Change(value)`: single values use `value`/`defaultValue`/`onValueChange`, checked state `checked`/`defaultChecked`/`onCheckedChange`, open state `open`/`defaultOpen`/`onOpenChange`. When both the old and the new name are given, the new value wins and both callbacks are called.

| Component | Deprecated (0.4) | Use instead (0.5) | Fires |
|---|---|---|---|
| Checkbox, Switch | `onChange(checked)` | `onCheckedChange(checked)` | both: on change only |
| RadioGroup, Rating, SearchBox, SpinButton, ColorPicker, SwatchPicker, TagPicker, TimePicker, DatePicker | `onChange(value)` | `onValueChange(value)` | both: on change only |
| Input, Slider | — (`onChange` stays the native event) | `onValueChange(value)` (added next to `onChange`) | every change |
| Combobox, Dropdown | `onOptionSelect(value)` | `onValueChange(value)` | `onOptionSelect`: every option activation, re-selecting included; `onValueChange`: on change only |
| TabList | `selectedValue`, `defaultSelectedValue`, `onTabSelect`, `vertical` | `value`, `defaultValue`, `onValueChange`, `orientation` | `onTabSelect`: every activation; `onValueChange`: on change only |
| Nav | `selectedValue`, `defaultSelectedValue`, `onNavItemSelect` | `value`, `defaultValue`, `onValueChange` | `onNavItemSelect`: every activation; `onValueChange`: on change only |
| Nav.Category | label taken from the first string child | `label` prop | — |
| TeachingPopover | `currentStep`, `defaultCurrentStep` | `activeStep`, `defaultActiveStep` | — |
| List | `selectionMode="multi"` | `selectionMode="multiple"` | — |
| DataGrid | `selectedKeys`, `defaultSelectedKeys` (Set), `onSelectionChange(Set)` | `selectedItems`, `defaultSelectedItems`, `onSelectedItemsChange(string[])` | both: on change |
| DataGrid | `sortColumn`, `sortDirection`, `defaultSortColumn`, `defaultSortDirection` | `sort`, `defaultSort` (`{ columnId, direction }` or `null`) with `onSortChange(sort)` | every header activation |
| Table | `Table.Head`, `Table.HeadCell` (types `TableHeadProps`, `TableHeadCellProps`) | `Table.Header`, `Table.HeaderCell` (flat `TableHeader`, `TableHeaderCell`; types `TableHeaderProps`, `TableHeaderCellProps`). The flat `TableHead` and `TableHeadCell` exports are new in 0.5 and exist only as deprecated aliases. | — |
| Stack | `direction` | `orientation` | — |
| Skeleton | `variant` (`text`, `rectangular` → `rounded`; `circular`) | `shape` | — |
| Text | `weight={400 \| 600 \| 700}` | `weight="regular" \| "semibold" \| "bold"` | — |
| Link | `variant` (type `LinkVariant`) | `appearance` (type `LinkAppearance`), same values | — |
| Tooltip | `variant="dark" \| "light"` | `appearance="inverted" \| "normal"` | — |
| Accordion (single mode) | `openItems`, `defaultOpenItems`, `onOpenItemsChange` | `openItem`, `defaultOpenItem`, `onOpenItemChange` (`string \| null`) | on change only |

**Callback semantics.** Value callbacks (`onValueChange`, `onCheckedChange`, `onOpenChange` and the deprecated `onChange` value aliases) fire only when the value changes. Event callbacks fire on every activation, as in 0.4, also when the current item is activated again: `onTabSelect`, `onNavItemSelect`, `onOptionSelect` (all deprecated), `onPageChange`, `onStepChange` and the new `Tree` `onItemSelect`. The DataGrid `onSortChange(columnId, direction)` form of 0.4 still works while neither `sort` nor `defaultSort` is given.

### Changed

#### Packaging

- The repository's `package.json` is named `@mortenbrudvik/waveui`, the name the npm package has always had (0.4's `package.json` said `waveui`; 0.4.0 was published as `@mortenbrudvik/waveui`).
- The build keeps one module per source file (ESM `.mjs` and CommonJS `.cjs`), so importing one component no longer bundles the whole library. `clsx` and `tailwind-merge` are no longer inlined into `dist`.
- Component and hook modules start with `"use client"`; the entry point, `cn`, the slot helpers and the types stay server-safe (React Server Components).
- CommonJS consumers get `index.d.cts` declarations (fixes TS1479 with the `require` condition).
- New runtime dependency `@floating-ui/react-dom` (popup positioning). `tailwindcss` `^4.1.0` is an optional peer dependency.
- New style entries: `./styles.css`, `./tailwind`, `./tailwind.css`, `./tokens.css`, `./variants`, `./variants.css`, `./preflight.css`, `./legacy-tokens.css` (see [Added](#added-2)).
- `repository`, `homepage` and `bugs` point to `github.com/mortenbrudvik/waveui`.

#### Styles

- `./styles` now points to precompiled, **unlayered** `dist/styles.css`: it works without Tailwind and contains no Preflight. It **requires `WaveProvider`**, which scopes the base styles and the native-element reset. Tailwind users import `./tailwind` instead (0.4's `./styles` was Tailwind source without `@source`, so components rendered unstyled).
- Preflight is opt-in (`./preflight.css`). The global `body` rules, the global `*` border color and the global `prefers-reduced-motion` override of 0.4 are gone: base styles apply only inside `.wave-root` and `.wave-portal`, and each component handles reduced motion itself.
- **`hidden`** hides every element inside `.wave-root` and `.wave-portal`, your own included: the base styles carry Preflight's rule (`[hidden]:not([hidden='until-found'])` gets `display: none !important`). Without it a display utility on a component root (`inline-flex`, `flex`, `grid`, …) beat the browser's own `hidden` rule, so `<Checkbox hidden>`, `<Button hidden>` or `<DatePicker hidden>` stayed visible without Preflight. `hidden="until-found"` keeps the browser's behaviour.
- CSS variables are prefixed `--wave-*`. Overrides of the 0.4 ramp names (`--brand-*`, `--grey-*`) keep working (they are read as fallbacks), but Wave no longer defines them, so app CSS that reads them (`var(--brand-80)`) gets nothing. **Overrides of the 0.4 semantic names (`--primary`, `--background`, `--border`, …) no longer affect Wave, and reads of them (`var(--ring)`) resolve to nothing**, unless `./legacy-tokens.css` is imported (deprecated compatibility layer; migration: rename the overrides and reads to `--wave-*`).
- Theme classes are `wave-light`, `wave-dark` and `wave-high-contrast`. WaveProvider still emits the legacy `dark` and `high-contrast` classes next to them, and Wave's CSS still honours them, but they set only `--wave-*` variables (no collision with shadcn/ui-style `--primary` definitions).
- `color-scheme` is set on the theme classes only, never on `:root`.
- The library no longer overrides Tailwind's radius scale or `font-sans`. Wave components use Tailwind's default radius names; their visual radii are unchanged.
- Token values: `muted-foreground` darkens to `#616161` (was `#707070`) for contrast. Light theme: `subtle-pressed` is grey-92 `#ebebeb`, the same as `subtle-selected` (0.4 components used `active:bg-[#e0e0e0]`), so primary and success text on a pressed subtle control reach 4.5:1. Dark theme: `primary` is brand-110 `#62abf5` (was `#479ef5`); primary, destructive and status fills use black foreground text; `destructive`/`error` is `#f48a94` (was `#dc626d`); `success` is `#5db55d` (was `#54b054`), so success text reaches 4.5:1 on `muted` and `subtle-selected`; info text and icons use the new `info-tint-foreground`, `#62abf5` (the `info` fill stays `#479ef5`). High contrast: `selected` is `#003a40` with white text (was `#1aebff`); `destructive`/`error` is `#ff6e6e` (was `#ff6060`), so error text reaches 4.5:1 on the pressed and selected subtle states and on `selected`.
- **Button** (0.4 put `min-w-[96px]` on every Button):
  - An icon-only Button (an `icon` and no rendered label) is square (20, 24, 32, 40 or 48px from extra-small to extra-large) with no minimum width and no horizontal padding. A labelled Button keeps a minimum width, now written `min-w-24` (6rem: 96px at the default 16px root font size, and it follows the root font size like the heights).
  - Every appearance draws a 1px border: transparent for `primary`, `subtle` and `transparent`, the stroke token for `outline` (which already had one). With border-box sizing (inside WaveProvider, with Preflight, and for a native `<button>`) the fixed dimensions are unchanged: the height, the square icon-only size and the minimum width. A content-sized Button of those three appearances whose label makes it wider than the minimum is 2px wider than in 0.4. With content-box sizing (a non-button `as` such as `as="a"` outside WaveProvider and without Preflight) it is also 2px taller.
  - Labels follow the px type ramp: extra-small 10px, small 12px, medium 14px, large 16px, extra-large 18px on a 24px line (0.4: extra-large was 14px, smaller than large). Small, medium and large were rem-based in 0.4: at the default 16px root they are unchanged, but they no longer scale with the root font size.
  - All colors are theme tokens (0.4 used light-theme hex values for hover, pressed and the outline border in every theme). Hover and pressed colors are gated (`not-disabled:not-aria-disabled:hover:` / `not-disabled:not-aria-disabled:active:`): they never apply to a disabled or `aria-disabled` Button, and they now work for `as="a"`. The gate gives them a higher specificity than a bare `hover:` class, so a `className="hover:bg-error"` no longer overrides the built-in hover color as it did in 0.4. Use the same prefix (`not-disabled:not-aria-disabled:hover:bg-error`, which replaces the built-in class) or the important modifier (`hover:bg-error!`, which also applies while the Button is disabled).
  - `Button as="a"` shows no link underline (`no-underline`); the `transparent` appearance still underlines on hover.
- **MenuButton** without a label (an icon and/or the menu indicator only) has no minimum width and compact padding (`min-w-0` with `px-1.5` extra-small and small, `px-2` medium and large, `px-3` extra-large, as SplitButton's menu half); a `className` still wins. A labelled MenuButton keeps `min-w-24`. Such a MenuButton (an icon, the menu indicator or both, no label) without `aria-label`, `aria-labelledby` or `title` logs a development warning once, like an icon-only Button.
- **Direction.** Mirrored parts use Wave's own `wave-rtl:` variant instead of Tailwind's `rtl:`: the chevrons of DatePicker, Tree, Breadcrumb and Pagination, the PresenceBadge out-of-office arrow, the Switch thumb, the Select chevron position and the indeterminate ProgressBar keyframes. `wave-rtl:` follows the element's own direction (`:dir(rtl)`, with a `[dir=rtl]` fallback for browsers without `:dir()`), so an LTR subtree of an RTL page is no longer mirrored (the checked Switch thumb was drawn outside its track, and the Select chevron sat over the text). DOM class change: `rtl:-scale-x-100` is now `wave-rtl:-scale-x-100`.
- **`./styles` no longer ships stray global classes** that Tailwind generated from words in comments and non-class strings: `.blur`, `.collapse`, `.container`, `.end`, `.filter`, `.hover:bg-error!`, `.inline`, `.list-item`, `.lowercase`, `.not-disabled:not-aria-disabled:hover:bg-error`, `.outline`, `.resize`, `.ring`, `.select-all`, `.shadow`, `.sm:inline`, `.start`, `.static`, `.table`, `.text-input`, `.transform` and `.visible`. They were unlayered, so they restyled an app's own `.collapse`, `.container` or `.table` (for example Bootstrap's navbar and accordion).
- **Field boundaries and the invalid look.** Combobox and Dropdown add the accessible bottom stroke (`border-b-stroke-accessible`, 3:1 per WCAG 1.4.11) to their border, as Input does; the TagPicker tag area and the ColorPicker hex field change from `border-border` to `border-input` with the same bottom stroke. Every text-entry control and picker draws the invalid state with one destructive recipe (`border-destructive`, and a destructive bottom stroke while focused) whenever it ends up `aria-invalid="true"` (its own error, a Field error or your `aria-invalid`; your `aria-invalid={false}` wins, and your `"grammar"`/`"spelling"` pass through without the error border, also on SpinButton and the ColorPicker hex field, which rewrote them to `true`; SpinButton keeps an explicit `aria-invalid={false}` on its input). New for Combobox and Dropdown (which used `aria-invalid:border-error`, so the focused stroke turned primary), TagPicker, DatePicker and TimePicker (which had no invalid border). Input, Select, Textarea, SearchBox, SpinButton and the ColorPicker hex field look the same (the hex field's `aria-invalid:border-error` classes are replaced by the shared ones). The ColorPicker opacity slider shows the shared focus ring.
- **SearchBox** draws its field on the root `<div>`: the border, the accessible bottom stroke, the background, the focus underline (also while the clear button has focus), the invalid border and the disabled look. The inner `<input>` is borderless and transparent, and the icon (or `contentBefore`), the text, `contentAfter` and the clear button sit side by side, so the slots no longer cover the text. `className`, `style` and `hidden` now style and hide the visible field box (as on SpinButton's root). The input's `ps-8`/`pe-9` and the absolute `start-2`/`end-8`/`end-1` positioning are gone. A `contentAfter` that renders nothing (`false`, `''`, `[]`, `<></>`) takes no room (it left an empty 8px padded box), and a `contentBefore` that renders nothing keeps the default search icon (`false`, `''` and `[]` removed it and left an empty padded box).
- **Image** sets its own sizing instead of relying on Preflight: it is never wider than its parent (`max-w-full`), and with the default `fit` its height follows its width (`h-auto`), so `width`/`height` attributes keep the aspect ratio. With `fit` `none`, `center`, `contain` or `cover` the box keeps its height, and a `className` height (`h-48`) replaces the automatic one. A default-fit image sized only by a `height` attribute shows at its natural size, as with 0.4's Preflight: size it with `className`. `fit="none"` keeps the image's top-left corner in view (`object-left-top`, as in Fluent); it rendered like `fit="center"`.
- **Checkbox, Switch and RadioGroup** items set their own zero padding (and a transparent background for the unchecked box and the radio circle), so an app's global `button { padding; background }` rule no longer shifts the thumb or fills the boxes. The same holds for the SearchBox clear button, the SpinButton step buttons, every DatePicker button (clear, calendar toggle, month buttons, days), the TimePicker clear button, the TagPicker remove buttons and the SwatchPicker swatches (padding and background), and the Dropdown button (vertical padding). Their label text uses the px type ramp (`text-body-1`, 14px/20px) instead of `text-sm`, identical at a 16px root. The Switch track is sized in px (40×20), so the px thumb stays inside it at any root font size.
- **Dialog** has a 1px `border-border` edge in every theme, like Popover and Menu, so it stays visible in high contrast and forced colors, where the shadow disappears. **Drawer** has the same edge on the side that faces the page.
- **Carousel** is its own stacking context (`isolate`), so its controls' `z-10` no longer paints over the page's sticky or fixed headers.
- **Overflow**: the row has a 4px padding (`p-1`), so its items' focus rings are no longer clipped. It has no negative margin, so its items sit 4px in from its edges and the row is 8px taller than its items; an explicit width on the root includes the padding. (Earlier 0.5 builds pulled the row back with a −4px margin, which made an edge-to-edge row reach 4px past its container and added a horizontal scrollbar to the page or to a scroll container around it.) Where nothing within 4px of the row scrolls, you may add the negative margin back (`className="-m-1"`). The overflow button wrapper changes from `end-0` to `-end-1` with `data-[overflow-pinned]:pe-1`.
- **Stepper**: the vertical connector's offset is `ms-3.75` (was `ms-[15px]`), so it stays centred under the step circle at any root font size.

#### Behaviour

- **WaveProvider** paints the themed background, text color and font on its root (`bg-background text-foreground font-wave text-body-1`; your `className` wins). An unknown `theme` value falls back to light with a development warning. A nested provider inherits `theme`, `dir` and `portalContainer` from the enclosing provider when it omits them (before, it fell back to `'light'`, `'ltr'` and `document.body`, so a theme-only panel inside an RTL app laid out LTR, reversed its arrow keys and sent its overlays to `document.body`). Pass `portalContainer={null}` to send a nested subtree's overlays to `document.body`.
- **Triggers.** `Dialog.Trigger` and `Popover.Trigger` no longer render a wrapper `<span>` by default: their props and `className` merge onto the child. `asChild={false}` restores the span, and a child that does not forward `ref` falls back to the span automatically with a development warning. The new `Drawer.Trigger` and `Menu.Trigger` work the same way. A Fragment around one element (`<><Button /></>`) counts as that element, with no span and no warning (also for `Dialog.Close`, `Drawer.Close` and `Breadcrumb.Item asChild`). A wrapper span (`asChild={false}`, the automatic fallback, or text or several children) no longer carries `aria-haspopup`, `aria-expanded` and `aria-controls`, which a generic element may not have (axe `aria-allowed-attr`): they go to the first element in the tab order inside the span, so a button there is announced as opening the popup (set after mount, so absent from server HTML; dropped when the span holds no such element; an element that stops being the target gets its own values back). A span you made the trigger itself (a `role` such as `button` and `tabIndex={0}`) keeps them, in the server HTML too. A span given such a role but no `tabIndex` of 0 or more (only the role, or the role and `tabIndex={-1}`) is not the trigger: the element in the tab order inside it gets them after mount (so they are not in the server HTML for that form), and the span gets them after mount only when nothing inside it is in the tab order. `tabIndex` alone (`0` or `-1`) leaves the span generic, so the element inside it gets them (around text they are dropped). Every focus return of `Menu`, `Popover`, `Dialog` and `Drawer` goes to the element that carries them, through the same trigger rule: Escape, an outside press that leaves focus on the page, item activation and Tab (Menu's went to the element after the trigger), Shift+Tab from the popup back to the trigger, `Dialog.Close`/`Drawer.Close`, and the return to a popup's trigger when a Dialog opened from the popup as it closed. For a `tabIndex={-1}` span that is the element inside it, also when a press focused the span itself (Safari does that for a click on the button inside); the span takes focus back only when nothing inside it can.
- **Dialog and Drawer** no longer set `aria-modal="true"`; they make the rest of the page `inert` while open, so toasts and live regions stay available. They trap focus including allow-listed toasts, lock page scroll with a counter shared by stacked overlays, and no longer close when a drag that started inside them ends on the backdrop. On close, focus goes to `finalFocusRef` when given. Otherwise it returns, as in 0.4, to the element that had focus when the modal opened (a trigger's wrapper span resolves to the element inside it, see Triggers): the trigger for a trigger click, but also the parent's own button of a controlled Dialog, or a text field that had focus when a keyboard shortcut opened it (a mounted trigger does not take precedence over it). New in 0.5: when nothing had focus (a modal opened from code, or a click in Safari, which does not focus the clicked button), focus goes to the trigger clicked in this open session, else to the first mounted trigger; when the target is gone, it falls back to a mounted trigger, then to an element next to where the opener was (the next row's action after a delete), then to the overlay below. A focus trap (Dialog, Drawer, the DatePicker calendar) returns focus that lands outside it in a microtask after the `focusin`, not inside the `focusin` dispatch: a test that moves focus outside an open dialog programmatically flushes microtasks (`await act(async () => {})`) before it asserts where focus went. A `title` that renders nothing (`[]`, `true`, an array of empty values) counts as no title, so `Dialog.Title`/`Drawer.Title` or `aria-label` name the surface (it rendered an empty heading that left the surface unnamed).
- **Portals.** Popover content, the Tooltip visual, open listboxes (Combobox, Dropdown, TagPicker, TimePicker), the DatePicker calendar, `Menu.Popover`, the AvatarGroup overflow popup, the InfoLabel popup and the Toaster region render in a portal (0.4: only Dialog and Drawer). Portaled content inherits the provider's theme and direction. Popups position themselves with flipping and shifting to stay in the viewport.
- **Layered dismissal.** Escape and outside presses close only the topmost layer: Escape in a Dropdown inside a Dialog closes the listbox, not the Dialog. Clicks inside nested portaled overlays count as inside. Clicking a toast never dismisses the overlay below it. A surface that closes when focus leaves it (Menu, the listbox popups of Combobox, Dropdown, TagPicker and TimePicker, the AvatarGroup overflow popup, the InfoLabel popup) decides in a microtask after the focus change, so a Popover, Dialog or portal with an `autoFocus` field opened from inside it no longer closes it: a test that moves focus outside with a synchronous `act(() => el.focus())` flushes (`await act(async () => {})`) before it asserts that the surface closed.
- **Tooltip** always renders a hidden inline `role="tooltip"` description and keeps it in the child's `aria-describedby` (the child's own ids are kept), so the description exists on the server and before the show delay. It can name its child instead (`relationship="label"`). It stays open while hovered, closes with Escape without closing an enclosing overlay, and hides immediately on blur. Focus and blur inside a popup that its child renders in a portal (a DatePicker calendar, a listbox) no longer show or hide it and no longer reach the Tooltip's `onFocus`/`onBlur`; the pointer entering such a popup does not show it, and moving onto the popup hides it. `onMouseEnter`/`onMouseLeave` still follow React's tree (they also fire for the tooltip surface and such popups).
- **Popover** closes on Escape and outside presses (not presses inside overlays opened from it), returns focus to its trigger when focus was inside, and is named by `title`, `aria-label`/`aria-labelledby` or else its trigger. When the trigger is itself named through `aria-labelledby` (an icon-only Button inside `Tooltip relationship="label"`), the content points at the trigger's label elements (only ids present in the document), so it gets the trigger's name; a development warning fires when the trigger has no text to name it, and a `title` that renders nothing (`[]`, `[null, false, '']`) counts as no title. A consumer `id` on `Popover.Content` is kept and the trigger's `aria-controls` follows it (0.4: `aria-controls` kept pointing at the generated id). In the keyboard order the portaled content follows its trigger, like 0.4's inline content: Tab from the open trigger enters it (also when a render-prop child does not apply the `onKeyDown` it receives), Tab past its last element continues after the trigger, Shift+Tab from its first element returns to the trigger (or, when nothing in the trigger can take focus, to the tab stop before it), and Shift+Tab from the element after the trigger enters it at its last element. For a trigger outside the tab order (a `<span>` with nothing focusable, or `tabIndex={-1}`), Tab from the tab stop before the trigger enters the content. With no tab stop before the trigger, the content is reached where it is portaled, at the end of the page, in both directions. After the focused last control of the content removes or hides itself (a "Clear" button), Shift+Tab continues at the control before it. A Tab lap visits the content once: Tab from the last element of the page moves past the portaled content and leaves the page, and Shift+Tab from outside the page (the browser's own controls) reaches the page's last element first, outside every open popover's content (its focus handlers run before its blur handlers, so a Tooltip on it opens and closes as usual). After a Dialog, Drawer, nested Popover or picker popup opened from the content's last element closes, Tab from there continues after the trigger. Content that the Tab from the page end still reaches follows the document order, so Tab never cycles through the page while a popover is open. While a popover is open, a Tab key anywhere scans the page's tabbable elements once.
- **TeachingPopover** is uncontrolled by default (`defaultOpen` `true`): Close, Done and Escape now dismiss it without a controlled `open`. Focus moves into it on open and returns on close (with `target`, to the target when nothing had focus, such as a tour opened on page load); step changes are announced, and Back stays focusable (`aria-disabled`) on the first step. With `target`, the keyboard order treats it as if it followed the target: Tab past its last button continues after the target, Shift+Tab from its first button (or from the popover) returns to the target (for a target outside the Tab order, to the last control inside it, else to the control before it), Tab from there enters the popover, and Shift+Tab from the control after the target enters it at its last button; a Tab lap visits the popover once, as for Popover. With no control at or before the target (a tour pointing at a heading at the top of the page), the popover is reached where it is portaled, at the end of the page, in both directions. A consumer `onKeyDown` is composed with this Tab handling (`preventDefault()` on Tab opts out).
- **Default positions follow the direction.** `Drawer` defaults to `position="end"` and `Toaster` to `position="bottom-end"`: unchanged in LTR, on the left in RTL (0.4: `right` and `bottom-right`).
- **Boundary buttons** of Pagination (First/Previous/Next/Last) and Carousel (Previous/Next) use `aria-disabled` instead of `disabled`, so focus is not lost. Pagination clamps an out-of-range `currentPage` and reports the clamped page once through `onPageChange`.
- **Carousel** dots are buttons with `aria-current` (no tab roles). Inactive slides are `inert` and `aria-hidden`. `autoPlay` adds a Pause/Start control, pauses on hover and focus, starts stopped for reduced motion, and stops at the last slide without `loop`. Slides are the `Carousel.Item` children, written directly or in Fragments (nested ones too). Other children are not rendered, and a development warning now says so once; a component that renders `Carousel.Item` itself is not a slide.
- **DataGrid** rows are no longer individual tab stops: the grid has one Tab stop and the APG grid keyboard model. Sortable headers are buttons. Selectable grids render a selection column header ("Select all rows" in multiple mode), name each row's control after its first cell, and set `aria-multiselectable`. Rows without `rowId` get no selection control (development warning). `columns` renders the header when no `DataGrid.Header` is given. With `selectionMode="single"` one row is selected, the first selected id whose row is rendered (also after a runtime switch from multiple): the radios, `aria-selected` and the highlight agree, and several ids warn once in development.
- **Menu**: the container is no longer a tab stop (roving tab index on the items). Passing `open`, `defaultOpen` or `onOpenChange` (even `false`) makes a popup menu, and a `Menu.Item` rendered in a popup menu outside `Menu.Popover` warns in development. Clicks and keys from a portal opened inside a `Menu.Item` (a Popover, a Dialog) no longer activate the item, close the menu, run typeahead or swallow Space and Enter typed into its fields, and Tab inside such a portal no longer closes the menu; the item's `onClick` (on an enabled item: a disabled one calls none, as a disabled button) and `onKeyDown` still receive the bubbled events (React semantics). **List**: options use a roving tab index; a selectable List whose items have `action`s switches to grid semantics. An `action` that renders nothing (`[]`, an array of `null`/`false`/`''`) is no action, so such a List stays a listbox.
- **Typeahead** (Menu, selectable List, Tree, Dropdown): a Space typed within 500 ms of a typeahead character continues the search instead of activating the focused item or committing, as in a native `<select>`, so typing "new y" reaches "New York". Keys typed in content inside an item, such as a List row's action button, are not typeahead. Characters typed with AltGr, which Windows reports as Ctrl+Alt (Polish `ł`, Romanian `ș`), are typeahead too, also in `useRovingTabIndex` with `typeahead`; Ctrl+Alt with an arrow, Home or End is still left to the browser, and Ctrl+Alt+Space is no character: it neither opens nor commits a Dropdown or Combobox list, never continues a search and does not activate a Menu, List or Tree item (Enter and Space with Ctrl, Alt or Meta are left to the page there). Roving typeahead (Menu, selectable List, Tree) passes over a matching item that cannot take focus (hidden by CSS) to the next match, so repeating the letter no longer gets stuck. `Menu.Item` typeahead matches the item's label only, so a non-string label (an i18n component) no longer starts with its icon's text (an emoji or icon-font ligature).
- **Toolbar and roving focus** (`useRovingTabIndex`, Toolbar, Menu): a control hidden by CSS inside the container (`display: none` or `visibility: hidden` on it or on an ancestor inside the container, or inside a closed `<details>`) is skipped by the arrow keys, Home/End and typeahead, never holds the Tab stop and gets `tabindex="-1"`; a toolbar hidden as a whole (inside a TeachingPopover that is still being positioned) keeps its items and its Tab stop. The `type="hidden"` input of a named value control is never an item. When an item's `focus()` does not move focus, the arrows, Home/End, `focusFirst()` and `focusLast()` move on to the next item (`onFocusMove` is not called for the refused one). With explicit `items`, values that are listed but not rendered, or are `hidden` or `inert`, no longer take the Tab stop computed during render, and an `itemSelector` the browser rejects logs a development warning. In a Toolbar, a nested composite (a RadioGroup, a TabList) or a control that uses the arrow keys itself (a text field, select, slider, spin button or editable combobox) no longer takes the only Tab stop: focusing it keeps the stop on the last focused other control, so Tab and Shift+Tab return to the toolbar (such an item holds the stop only when nothing else can). Left/Right move on from a Dropdown (select-only combobox), which keeps Up/Down, Home and End for its list; only editable comboboxes keep Left/Right.
- **Checkbox and Switch**: a consumer `onClick` fires once, on the control (0.4 fired it twice when the label text was clicked).
- **Composite controls** (Checkbox, Switch, SearchBox, SpinButton, Combobox, Dropdown, TagPicker, DatePicker, TimePicker) route `id`, the naming and validation ARIA attributes (`aria-label`, `aria-labelledby`, `aria-describedby`, `aria-invalid`, `aria-required`, `aria-errormessage`, `aria-details`), `tabIndex`, `autoFocus`, focus and key handlers (and native input attributes for text fields, `autoCapitalize` and `autoCorrect` included) to their focusable element. Other `aria-*` attributes stay on the wrapper. `ref` is unchanged (on the wrapper); the new `controlRef` reaches the focusable element.
- **Input with `contentBefore`/`contentAfter`** content: the bordered wrapper `<span>` receives `className`, `style` and `hidden`, so they size and hide the visible field; `ref`, `id`, `aria-*`, `data-*`, handlers and native attributes stay on the `<input>`. A slot value that renders nothing (`false`, `''`, `[]`) adds no wrapper: the Input renders as a plain `<input>` and `className` lands on it.
- **Checkbox, Switch and RadioItem** with `label` text are named through `aria-labelledby`, which points at that text (its `<span>` now has an `id`), enabled or disabled, so axe's contrast exemption for disabled controls covers the dimmed label. A plain `label="Accept"` keeps the name "Accept". A consumer `aria-label` still names the control alone, and no `aria-labelledby` is added. A consumer `aria-labelledby` comes first and the label text follows: `aria-labelledby="terms-heading"` (text "Terms") with `label="Accept"` gives "Terms Accept", not "Terms". Inside a `Field`, a Checkbox or Switch is named by the Field label followed by its label text. Because `aria-labelledby` takes precedence over `<label>` elements, a `<label htmlFor>` of your own that targets the control no longer adds to its name while the control has `label` text: add that label's `id` to `aria-labelledby` instead.
- **Callbacks.** Value callbacks (`onValueChange`, `onCheckedChange`, `onOpenChange`) skip no-op changes. Event-named callbacks (`onTabSelect`, `onNavItemSelect`, `onOptionSelect`, `onPageChange`, `onStepChange`) still fire on every activation. The deprecated `onChange(value)`/`onChange(checked)` aliases (Checkbox, Switch, RadioGroup, Rating, SearchBox, SpinButton, ColorPicker, SwatchPicker, TagPicker, TimePicker, DatePicker) are change-only like their replacements, so choosing the current radio or star again and pressing a Rating key at an end no longer emit (0.4 did).
- **Rating** cannot be cleared to 0 by keyboard: Left/Down stop at 1 star (APG radio group; 0.4 went down to 0 and emitted `onChange(0)`). A controlled `value={0}` (or a form reset to a `defaultValue` of 0) still clears it. `RatingDisplay` draws a fractional `value` as a partly filled star, filled from the inline start (`4.6` fills 60% of the fifth star), so the stars match its accessible name.
- **Controlled values.** A controlled value that becomes `undefined` now clears the component to its empty value (0.4 ignored it or crashed). A value that arrives after mount takes over.
- **Field** no longer overwrites a child's `id`, `aria-describedby` or `aria-invalid`, and merges only into its first element child (0.4 cloned every element child and gave each the same id). It leaves a Fragment and a role-less or presentational `div`/`span` wrapper alone (the library control inside is labelled through the Field context); a first child with an explicit widget role (`<div role="radiogroup">`) is named through `aria-labelledby` and no longer receives the id. It no longer puts `aria-required` on a `button`, `meter`, `output`, `progress`, button-type `<input>` or role-less custom element, or on an element whose explicit role does not support it. With `required`, Field now also sets the native `required` attribute on an `<input>` (not button types), `<select>` or `<textarea>` child and on the library Input, Select, Textarea, Slider, SpinButton and SearchBox, so browser constraint validation blocks submitting the form while the field is empty (0.4 set only `aria-required`). The choice and picker controls inside a required Field (Checkbox, Switch, RadioGroup, Rating, SwatchPicker, ColorPicker, Combobox, Dropdown, TagPicker, DatePicker, TimePicker) are required as well: they render their hidden input as a required input even without `name`, so the form does not submit until the control is checked, switched on or has a value, and the browser focuses the control when it blocks the submit. `<Field required><Switch /></Field>` blocks the submit while the switch is off. An explicit `required={false}` on the control opts it out of both the validation and `aria-required`, as the Field's first child or nested deeper. Give the `<form>` `noValidate` to keep 0.4's behaviour and validate in your submit handler. A read-only Combobox, TagPicker, DatePicker or TimePicker does not block the submit, like a native read-only input (`aria-required` stays and the value is submitted). The required asterisk is hidden from assistive technology, and the error message is a `role="alert"` element. A `label`, `hint` or `error` that renders nothing (`[]`, or an array of only `null`/`false`/`''` such as an empty `errors.map(…)`) counts as absent: the control stays valid, no empty alert renders and the hint shows. A first child's own `aria-invalid` (`<Input aria-invalid={false} />`) is kept while the Field has an error, as for controls nested deeper; the Field error still describes it.
- **Error messages.** `<Input|Select|Textarea error="text">` now renders the message after the control in a sibling `role="alert"` element linked by `aria-describedby` and `aria-errormessage` (pass `error={true}` for the flag-only look; inside a Field that shows its own error nothing changes). Input, Select, Textarea and SearchBox show the error border whenever the control ends up `aria-invalid="true"`, which includes an `error` on the surrounding Field or your own `aria-invalid`, not only their own `error` prop (0.4 drew it only for `error`; SearchBox never).
- **SearchBox** routes `readOnly` and the other native input attributes to its `<input>` (0.4 left them on the wrapper `<div>`, so the input stayed editable); a read-only SearchBox renders no clear button. Clearing moves focus back to the input. `dismiss` content that renders nothing (`false`, `true`, `''`, `[]`, or a Fragment of those) shows the default clear icon (0.4 rendered an empty clear button). Escape in a non-empty, editable field clears the text, calls `onValueChange('')` and `onClear`, keeps focus and is consumed, so an enclosing Dialog, Drawer or Popover stays open; in an empty field Escape still reaches them. Pressing the search icon, a slot or the field padding focuses the input (a control inside a slot keeps its own press), and controls in `contentBefore` are clickable (the slot was `pointer-events-none`). A form reset restores `defaultValue` (text, submitted value and clear button) and reports it through `onValueChange`.
- **MessageBar** `dismiss`: `null` is the only value that hides the dismiss button. A boolean counts as no slot, so `dismiss={false}` or `dismiss={true}` with `onDismiss` shows the default button (it was removed), and content that renders nothing (`''`, `[]`, an empty Fragment, a slot object or merged `<button>`/`Button` whose children render nothing, a Wave `Button` whose `icon` renders nothing) shows the default dismiss icon instead of an empty, invisible button.
- **Tag** `dismissIcon`: a slot that renders no content (`[]`, a childless `<button>`/`Button`, a slot object without `children`, also the deprecated button-object form without `children`) shows the default dismiss icon instead of an empty, invisible button, and a slot object without children styles that icon (`{ className: 'text-error' }` makes it red; a slot object that drew its icon only through CSS, such as an icon-font class on an empty element, now also contains the default icon). `dismissIcon={0}` renders "0". A Wave `Button` with both `icon` and children renders the icon followed by the children (the children were dropped). `onDismiss` or `dismissIcon` without `dismissible` logs a development warning (no dismiss button renders then, as before); an explicit `dismissible={false}` does not warn.
- **Dismiss and clear button names** (WCAG 2.5.3 Label in Name): a `<button>` or `Button` passed as MessageBar `dismiss`, SearchBox `dismiss` or Tag `dismissIcon` that renders a text label (at least two letters or digits, text from child components included) is named by that text. MessageBar and SearchBox drop their default name (MessageBar as in 0.4; SearchBox always said "Clear search" in 0.4), and Tag says the text plus the tag content ("Remove Cherry" instead of "Dismiss Cherry"), also for a `Button` with an `icon` and a text label. An icon or a lone character (`X`, `×`) keeps "Dismiss", "Clear search" or "Dismiss Cherry" (0.4 MessageBar named a `<button>X</button>` "X"). Text hidden only by CSS still counts as the label, so give such buttons an explicit `aria-label`. An `aria-label`, `aria-labelledby` or `title` on a SearchBox slot object now names the clear button (0.4 put it on the hidden content). Tag dismiss buttons are named by `dismissLabel` plus the tag content (0.4: a fixed "Dismiss").
- **Spinner** has the default name "Loading", set one animation frame after mount so it is announced.
- **TabList** selects its first enabled tab when uncontrolled without a default; disabled tabs are skipped by the keyboard. A controlled `value` that becomes `undefined` selects no tab and shows no panel, like `value=""`, and the TabList stays controlled (it selected the first enabled tab and turned uncontrolled).
- **DatePicker** default display format is `Intl.DateTimeFormat(locale, { year: 'numeric', month: '2-digit', day: '2-digit' })` and round-trips with the default parser (pass `locale` when rendering on the server). Typed text is committed on Enter, Alt+ArrowDown or blur only when it was edited; text that is not an available date is kept, marked invalid and reported through `onInvalidInput`. Every emitted date is local midnight. When a controlled parent selects another day, rejected typed text is replaced by the new date and its error, `aria-invalid` and alert are cleared (text the user is still typing is kept). Switching to `readOnly` or `disabled` while the user is typing drops the typed text and its error, so a later blur commits nothing. A form reset emits `defaultValue` as local midnight, and only when the selected day changes. A `locale` that `Intl` rejects (the POSIX `de_DE`) falls back to the runtime default locale with a development warning.
- **TimePicker**: a complete typed time activates its own option, not an earlier option that merely contains the text (`2:00 PM` commits `14:00`, not `12:00`). Enter or leaving the field commits a complete typed time within the bounds (0.4 discarded it). Erasing the text and pressing Enter or leaving the field clears the value (`onValueChange('')`), as DatePicker does (`onValueChange(null)`). Opening with a value shows every option. A complete time in any accepted spelling (`2:00pm`, `09:00 AM`, `14:00:00`, `2:00 p.m.`) keeps its option listed and active, so "No matching times" is no longer announced for a time that Enter accepts. While the text is edited, Enter never submits the form: a complete time within the bounds is committed, other text is kept; unedited text lets Enter submit. Switching to `readOnly` or `disabled` while the user is typing drops the typed text. An uncontrolled list closed by disabling or `readOnly` reports `onOpenChange(false)` and stays closed when re-enabled. The invalid `step` and `minTime`/`maxTime` diagnostics are development warnings (`console.warn`, once per invalid value per page) instead of `console.error` on every mount and effect run of every instance.
- **Combobox** filters the options in both modes (0.4 filtered only with `freeform`). Without `freeform`, blur and Escape restore the selected option's label and never commit free text. Display text is the option label (0.4 showed the raw value for `value`/`defaultValue`), also in server-rendered HTML.
- **Options.** `hidden` on an `Option` works like a native `<option hidden>`: the option is never highlighted or reached by the arrow keys, Home/End, typeahead or Tab, and never committed with Enter; a selected hidden option (a placeholder) still shows its label in the Dropdown or Combobox. `hidden` on an `OptionGroup` does the same for every option in it, nested groups included (those options carry the `hidden` attribute themselves), and a group whose options are all hidden is hidden. When every option is hidden, Dropdown, Combobox and TagPicker open no empty surface (`aria-expanded` stays `false`). Combobox and TagPicker announce "No matches" through a visually hidden `role="status"` element that is always mounted in the component root and holds the text only while nothing matches.
- **ColorPicker**: the hex text is a draft. Complete 6- and 8-digit values apply while typing (6 digits keep the current opacity); `#rgb`/`#rgba` apply on blur or Enter (`#rgb` keeps the current opacity); surrounding whitespace is dropped. Invalid text is no longer reverted on blur (0.4 discarded it silently): it is kept and flagged (`aria-invalid` plus the `hexError` description) and never reaches `onValueChange`. It stays flagged until it is corrected or cleared, or the value changes elsewhere (a preset, the opacity slider, the parent, a form reset); meanwhile the form submits the last applied color. Enter still submits the form, with the color just applied. The opacity slider edits the value's alpha byte. `defaultValue` is shown, submitted and reported like every edit, as a lowercase `#rrggbb`, or `#rrggbbaa` when not opaque (`#ABC` becomes `#aabbcc`, `#0f6cbdff` becomes `#0f6cbd`); a form reset reports it through `onValueChange` only when the color changes (the same color in another spelling is no change). A preset whose alpha digits are below `f`/`ff` (`#rgba`, `#rrggbbaa`) logs a one-time development warning that its alpha is ignored, and such a string preset is announced by the `#rrggbb` color it applies (an opaque alpha changes nothing).
- **TagPicker**: Backspace in the empty input moves focus to the last tag, and a second Backspace (or Delete) removes it (0.4 removed the last tag at once). Additions and removals are announced ("Apple added, 2 selected"). A disabled TagPicker's remove buttons leave the tab order. Selected values without a matching option are shown with their raw value. Typing a filter makes the first match active, so Enter adds it and keeps the list open instead of submitting the surrounding form (as in Combobox); nothing is active on open or once the text is cleared, and Enter with nothing active still submits. A form reset calls `onValueChange` only when it changes the tags (compared in order), with a copy of `defaultValue`. Like DatePicker and TimePicker, a TagPicker rendered on the server with `defaultOpen` (or `open`) is closed in the server HTML and opens once hydrated, so no ARIA reference points at a list that is not there.
- **Toasts.** `useToastController` outside `<Toaster>` throws in development (0.4 dropped the toasts silently; the 0.4 guide showed a sibling setup): wrap the app in `<Toaster>`. Toasts are announced through permanent live regions, and their timers pause while a toast is hovered or focused and while the page is in the background (the window has lost focus, or the page is hidden, as in a background tab, also for a Toaster that mounts there). When a toast that contains focus goes away, focus moves to the next toast (or the previous one when the last toast goes), or back to the element that was focused before focus entered the toasts once no toast is left. While an open modal panel covers the toasts' corner (a Drawer on the same side), the toasts move beside it.
- **`announce()` / `useAnnounce`**: a message sent while a repeated message waits for its next-frame rewrite replaces it (the last call wins); the stale repeat was written over the newer message and read last.
- **Button**:
  - The `type="button"` default of a native `<button>`, and the `role="button"`/`tabIndex={0}` defaults of a non-interactive `as` (`div`, `span`, …), also apply when the prop is passed as `undefined` or `null`: a wrapper that forwards `type={type}` no longer drops `type="button"` and submits its form. Any other explicit value still wins (`type="submit"`, `role="link"`, `tabIndex={-1}`). A custom `as` component still gets no `type` default, as in 0.4: pass `type` yourself inside a form.
  - A non-interactive intrinsic `as` gets `role="button"`, a tab stop and Enter (key down) / Space (key up) activation. Space activates only after an unprevented Space key down on the element itself; blur or a `preventDefault()` in your key handlers cancels it.
  - `disabled` reaches the element as the native attribute only for `button` (the default), `input`, `select` and `textarea`. Every other `as` — `a`, `div`, `span` and any custom component, including router links and styled or motion components that render a native `<button>` (0.4 passed `disabled` through to them) — gets `aria-disabled="true"` and `tabIndex={-1}` (after the rest props, so a consumer value cannot re-enable it). Its click is prevented and stopped (ancestor `onClick` handlers do not run, as with a native disabled button), Enter and Space do nothing, and an `<a>` drops its `href` and keeps `role="link"`. A custom component that renders a native `<button>` therefore loses the native `:disabled` state and its own `:disabled` styling; it leaves the tab order but can still take focus from a mouse click. Style such components on `[aria-disabled="true"]`.
  - A consumer `aria-disabled="true"` on an enabled Button shows the disabled look and suppresses hover and pressed colors, but the Button stays focusable and its handlers still run (guard them yourself).
  - The `icon` slot renders with `aria-hidden="true"` (a slot object can override it), so icon text or emoji is no longer part of the accessible name. An icon-only Button without `aria-label`, `aria-labelledby` or `title` logs a development warning (once). An `icon` that renders nothing (`''`, an empty array or Fragment, e.g. from `icon={name && <Icon />}`) counts as no icon.
- **Link**: `inline` links are always underlined; a disabled link drops its `href`, keeps `role="link"` and gets `aria-disabled` and `tabIndex={-1}` that a consumer value cannot override.
- **Nav**: activating a disabled item never selects it; a disabled item whose value is the current value still shows as current (`aria-current="page"`). Categories containing the selected item start open (`value` or `defaultValue`; `defaultOpenCategories`, even `[]`, replaces this). Breadcrumb.Item and Nav button items (no `href`) no longer render a `rel` attribute. A click that opens a link elsewhere (Ctrl/Cmd/Shift/Alt-click, a mouse button other than the main one, a `target` other than `_self`, a `download` link) selects nothing: `aria-current` stays and `onValueChange`/`onNavItemSelect` are not called, while your `onClick` still runs and the click is not prevented. When your `onClick` calls `preventDefault()` (client-side routing), the browser opens nothing elsewhere and the item is selected, whatever the modifiers.
- **Breadcrumb** renders each element of a Fragment child (`{isAdmin && <>…</>}`) as its own list item with separators (the whole Fragment was one `<li>`).
- **Breadcrumb.Item** without `href` renders a `<button type="button">` when it has `onClick`, plain text otherwise (0.4: an unfocusable `<a>` styled as a link). Its text and current-page spans no longer render button-only or link-only attributes (`disabled`, `type`, `form*`, `name`, `value`, `target`, `rel`, `download`, `hrefLang`, `ping`, `media`, `referrerPolicy`); a development warning fires for `disabled` on a text or current item. A link item takes `disabled`, as Link does, and treats `aria-disabled="true"` the same way: no `href`, `role="link"`, `aria-disabled="true"`, `tabIndex={-1}`, and the click is cancelled without calling `onClick`. An `asChild` element gets the same attributes (an `<a>` also drops its `href`) and loses its own `onClick`; the cancelled click keeps router links from navigating. An enabled `asChild` element receives the item's `href` as a default (its own `href` wins; it was dropped), and with `current` it gets the shared focus ring and the disabled styles (opacity and cursor while `aria-disabled`).
- **Card** with `onSelect` is keyboard-operable: `role="button"` with Enter/Space and `aria-pressed` (default `selectionControl="card"`), or a built-in checkbox (`selectionControl="checkbox"`) for cards with actions. Clicks and keys inside nested interactive elements never select the card.
- **Stepper** exposes the active step with `aria-current="step"` and announces completed and error steps; `onClick` of a disabled or unreachable step is not called.
- **Pagination** with `boundaryCount={0}` marks the pages before and after the shown range with an ellipsis, and shows a single missing first or last page instead (`totalPages={20}`, `currentPage={10}`, `siblingCount={1}`: … 9 10 11 …). No gap marker was shown.
- **Table and DataGrid** scroll horizontally in their wrapper (0.4: `overflow-hidden` clipped wide tables); a horizontally scrolling Table wrapper is a focusable named region.
- **Avatar** in initials or icon mode is a named image (`role="img"`, `aria-label={name}`); without a name it is decorative. A failed image falls back to the icon or initials; an avatar named only by its image slot's own `alt` keeps that name after a load failure (the fallback gets `role="img"` and `aria-label`). An image slot whose `alt` is `undefined` (`image={{ src, alt: user.photoAlt }}`) takes the default `alt` (`name`, or `''`) instead of rendering no `alt`. A falsy or empty `badge` (`null`, `false`, `''`, `0`, `NaN`, or a collection of only such items, as in `badge={count && <CounterBadge … />}` with `count` 0) renders no badge and no wrapper, as in 0.4.
- **PresenceBadge** is a named image (`role="img"`, named by its status: "Available", "Busy", …) instead of `role="status"` (0.4), which made every badge an implicit live region. Tests that query a badge with `getByRole('status')` use `getByRole('img', { name: 'Available' })`.
- **AvatarGroup** is a group (`role="group"`); name it with `aria-label` or `aria-labelledby` (a development warning asks for one). With `max`, the overflow `+N` is a `<button>` named "N more" (`overflowLabel`) instead of plain text in a `<span>`: it is a new tab stop and opens a popup (`role="dialog"`, portaled) that lists the hidden members' names. Tests find it with `getByRole('button', { name: '2 more' })`. Members inside a Fragment count, overlap and are listed one by one (a Fragment was one member for `max`). A negative `max` shows only the overflow button, a fraction is rounded down, and `NaN` shows every member.
- **Persona** makes its avatar decorative, so the name is announced once. A `badge` or `avatar` slot that renders nothing (`0`, `[]`, an all-empty collection) counts as not given, so the `status` badge and the built-in avatar show.
- **InfoLabel** shows its information in a popup on hover, keyboard focus or click (a toggletip), linked as the button's description (0.4: a native `title`).
- **Divider** with a label is one separator named by the label; a vertical divider shows its label. Children that render nothing (`''`, an empty array, or a collection of only empty items, such as an empty `.map()` result) are no label, so the divider stays a plain `<hr>` (or plain vertical line); `0` is still a label.
- **ProgressBar** clamps `value` to `0…max` (also for `aria-valuenow`), guards `max <= 0`, warns without a name, and pulses at full width for reduced motion.
- **Skeleton** placeholders are `aria-hidden` by default, and a consumer `aria-hidden` now overrides it (0.4 forced it after the rest props); `Skeleton.Group` marks the loading region busy.
- **Duplicate values** warn once per value in development: several `Accordion.Item`s (they open together and share ids), RadioGroup items (also when you override the group's `role`), `TabList.Tab`s (panels may still share one), `Tree.Item`s, Nav items (`Nav.Item` and `Nav.SubItem` share values) or categories with the same `value`, `List.Item`s of a selectable List with the same `value` (they are selected together), DataGrid rows with the same `rowId` (in every selection mode), and OverflowItems with the same `itemId` (they are hidden and shown together). **Tree** also warns when a `Tree.Item` is rendered inside the label of another item: nested items must be `Tree.Item` elements in their parent's children (directly, in Fragments or from a render function such as `children.map(renderNode)`), not rendered by a recursive component.
- **Content that renders nothing** is treated as absent everywhere the library checks for content, with one rule: `null`, `undefined`, booleans, `''`, and an array, `Set`, generator or Fragment of only those at any depth (`[]`, `<></>`, `<>{false}</>`); `0` is content (the icon slots of Avatar, Menu, Nav, Tree, Breadcrumb and Stepper, and the Avatar and Persona badges, also treat `0` as nothing). Newly covered: an empty Fragment in the icon slots of Avatar, Menu, Nav, Tree and Breadcrumb, the Input slots, the Field label, hint and error, the Dialog, Drawer and Popover titles, Divider, Persona, Carousel, Tag and List; a Button `icon` or MenuButton `menuIcon` that is an empty `Set` or a Set or generator of empty values (no icon span, no icon-only sizing); a CompoundButton `secondaryText` of `true`, `[]`, `<></>` or a Set of empty values (no second line); a Toast body of `''`, `true`, `[]` or `<></>` (no empty body line, also for a Toaster toast dispatched with `body: ''`); a Tag `dismissIcon` of `<></>` (the default dismiss icon); a `List.Item` `action` of `<></>` (no action); a `Card.Header` `title` or `subtitle` of `[]` (no element, so a checkbox card warns about its missing name; `title={0}` renders and names the checkbox); and a `Stepper.Step` `icon` that renders nothing (`''`, `0`, `[]`, a list or generator of nothing), which keeps the step number or the check mark.
- **Parts outside their root.** A compound part rendered outside its root still throws `[WaveUI] <Part> must be used within <Root>` in development. In production it logs that error once per message per page (it logged on every render; the registry is shared by every copy of the library) and renders inert. The texts lost their trailing period, for example `[WaveUI] TabList.Tab must be used within <TabList>`, `[WaveUI] Popover.Trigger must be used within Popover`, `[WaveUI] ListItem must be used within a List` and `[WaveUI] Option must be used within a listbox (Combobox or Dropdown)`. `useToastController` outside a `<Toaster>` logs its unchanged error the same way in production.

#### DOM structure

- Avatar with `badge`: `ref`, `className` and rest props now land on the outer wrapper; `role="img"` and the name stay on the avatar visual.
- `Tree.Item`: `ref` and rest props move from the role-less wrapper to the `role="treeitem"` element (still a `div`), and the child group is nested inside it.
- Stepper keeps its root `<div>` and adds an inner `<ol>`/`<li>` list.
- Combobox, Dropdown and TagPicker render their option list inline and `hidden` while closed, and in a portal while open.
- `OptionGroup` (`Combobox.OptionGroup`, `Dropdown.OptionGroup`, flat `ComboboxOptionGroup`/`DropdownOptionGroup`) renders `<li role="presentation">`, which carries `ref`, `className` and rest props, containing the label `<div role="presentation" id>` and a `<ul role="group" aria-labelledby>` of the options. 0.4 rendered `<div role="group" aria-label={label}>` with ref, className and rest props on that div; the group is now named through `aria-labelledby`.
- TagPicker renders its tags as a `role="list"` named "Selected", and while tags exist the input is described by a hidden summary ("Selected: Apple, Banana").
- The Popover root no longer renders 0.4's `<div class="relative inline-block">` around trigger and content: it renders only its children, and `Popover.Content` is portaled with fixed positioning. Layouts that relied on the wrapper's inline-block box or positioning context change.
- The Tooltip wrapper `<span>` was `relative inline-block` and is now `inline-block` (the visual is portaled, so the positioning context is gone). It always contains the hidden `role="tooltip"` description element.
- The TeachingPopover step dots were `role="group" aria-label="Steps"` and are now `aria-hidden` decoration; the heading carries a visually hidden "step n of m".
- Input, Select and Textarea with a string `error` render an extra sibling `<span role="alert">` after the control (`ref` and `className` stay on the control).
- The Toaster region is portaled (0.4 rendered it in place).
- Combobox and TagPicker: the visible "No matches" row in the popup is `aria-hidden="true"` and no longer has `role="status"`; the announcement comes from a visually hidden `role="status"` element in the component root. Tests that query the row by role query the status element instead.
- Options inside a hidden `OptionGroup` carry the `hidden` attribute themselves.
- A `Menu.Item` with a non-string label wraps it in a `<span data-menu-label="">` (the typeahead text).
- The wrapper `<span>` of a trigger (`asChild={false}` and the fallbacks) no longer carries `aria-haspopup`, `aria-expanded` or `aria-controls`; the first element in the tab order inside it does (see Triggers under [Behaviour](#behaviour-2)).
- `DataGrid.Row` renders its children with Fragments flattened (keys from the flattened list).

#### Types

- `SearchBox.dismiss`, `MessageBar.dismiss` and `Tag.dismissIcon` are `Slot<'span'> | SlotObject<'button'>` (the 0.4 button-object form still compiles; deprecated).
- `SlotObject` is widened: every attribute of the slot's element is accepted (`{ src, alt }` on an image slot), `as` takes any element type, and slots accept iterables (arrays, `Set`, generators). `Slot<T>` is `SlotObject<T> | React.ReactNode`, so a value typed `React.ReactNode` (promises included) can be passed to every slot prop (`icon`, `menuIcon`, `contentBefore`/`contentAfter`, `image`, `avatar`, …). An attributes object typed by an interface (`React.ImgHTMLAttributes<…>`) still has to be spread: `image={{ ...imgProps }}`.
- Polymorphic components type-check `as`-specific props: `<Button as="a" href target>` compiles, while `<Button as="a" formAction>` and anchor props on the default button are errors. `ButtonProps` is now `ButtonProps<C extends React.ElementType = 'button'>`; plain `ButtonProps` is still the 0.4 default-tag type, extendable by interfaces, with `ref: React.Ref<HTMLButtonElement>`. The same applies to CompoundButton, Link, Text, Toolbar, Card and its parts, Stack, Flex, Grid, Tag and Divider, which also export their `*OwnProps`. `React.ComponentProps<typeof X>`, `Parameters<typeof X>`, `React.memo(X)` and Storybook's `Meta<typeof X>` of these components are the checked default-element props (`ButtonProps`), as in 0.4: `PolymorphicComponent` has a trailing default-element call signature. Code that passes `as`-specific props through such a type (story args `as: 'a', href` on `Meta<typeof Button>`) types them with the element: `ButtonProps<'a'>`, `StoryObj<ButtonProps<'a'>>`.
- Array props that the library only reads accept readonly arrays (`as const` arrays, immutable state): Accordion `openItems`/`defaultOpenItems` (both modes), DataGrid `columns`/`selectedItems`/`defaultSelectedItems`, List `selectedItems`/`defaultSelectedItems`, Nav `openCategories`/`defaultOpenCategories`, SwatchPicker `items`, TagPicker `options`/`value`/`defaultValue`, TeachingPopover `steps`, Tree `expandedItems`/`defaultExpandedItems` and `useRovingTabIndex`'s `items`. Callbacks still receive a new, mutable array.
- `ref` is declared in every Props interface (0.4 added it through an intersection on the component).
- `Image.alt` stays optional (development warning when missing); `StrictImageProps` is exported for apps that want it required at compile time.
- `OptionGroupProps` extends `React.LiHTMLAttributes<HTMLLIElement>` and its `ref` is `React.Ref<HTMLLIElement>` (0.4: `React.HTMLAttributes<HTMLDivElement>` and a div ref), so passing a `RefObject<HTMLDivElement>` to `OptionGroup` is a type error.
- `AccordionProps` (single/multiple union), `DataGridProps` (sort-API union), `NavItemProps`, `NavSubItemProps` and `BreadcrumbItemProps` (link/button unions) are union types; 0.4 had interfaces. `interface X extends NavItemProps {}` no longer compiles (TS2312): extend a branch (`AccordionSingleProps`/`AccordionMultipleProps`, `DataGridBaseProps`, `NavItemButtonProps`/`NavItemAnchorProps`, `BreadcrumbItemAnchorProps`/`BreadcrumbItemButtonProps`) or intersect (`type X = NavItemProps & { … }`). `React.ComponentProps<typeof Nav.Item>` (and of `Nav.SubItem` and `Breadcrumb.Item`) resolves to the last overload (`*DynamicProps`).
- Nav.Item and Nav.SubItem handler typing: with a string `href`, unannotated handlers are typed on `HTMLAnchorElement` (0.4: `HTMLButtonElement` for every item), so a 0.4 handler that reads a button-only member such as `e.currentTarget.form` no longer compiles on a link item. With `href={maybe}` (`string | undefined`), handlers are typed on `HTMLAnchorElement | HTMLButtonElement`, and `href={maybe}` combined with `target` is a type error. Items without `href` keep `HTMLButtonElement`. Handlers already typed as `React.MouseEventHandler<HTMLButtonElement>` still compile on link items (React handler types are bivariant). Breadcrumb.Item handlers, typed on `HTMLElement` in 0.4, are now typed on the rendered element; existing handlers still compile.
- Routed handlers are typed on the focusable element: Checkbox and Switch `onClick`, `onFocus`, `onBlur`, `onKeyDown` and `onKeyUp` on `HTMLButtonElement` (0.4: the `<label>`); Combobox and TagPicker focus and key handlers on `HTMLInputElement`, Dropdown's on `HTMLButtonElement`; SearchBox and SpinButton native input props and handlers on `HTMLInputElement` (0.4: `HTMLDivElement`); DatePicker and TimePicker `onFocus`, `onBlur`, `onKeyDown` and `onKeyUp` on `HTMLInputElement` (they run on the input; they were typed on `HTMLDivElement`).
- `PopoverTriggerChildProps` (the render-prop argument of `Popover.Trigger`) declares `onKeyDown: React.KeyboardEventHandler<HTMLElement>` as a required member, like `onClick` and `ref`.
- `OptionProps.hidden` and `OptionGroupProps.hidden` are declared and documented (the type is unchanged; both were only inherited from `LiHTMLAttributes`).
- `ListProps` takes the `selectionMode` literal as a type parameter (`ListProps<M>`), which makes the single-mode props type errors with `selectionMode="multiple"`; plain `ListProps` accepts every mode.

### Fixed

Highlights, grouped by area:

- **Theming**: text is readable in the dark and high-contrast themes (WaveProvider paints the foreground and background); nested light providers inside dark ones work and keep the enclosing provider's direction and portal container; `WaveProvider` no longer warns about its own default theme; every component uses theme tokens, so Button, Checkbox, Switch, Rating, badges, MessageBar, Toast, Tooltip and the pickers keep their contrast in every theme; native controls get the right `color-scheme`.
- **Packaging**: `./styles` produces styled components without any setup beyond `WaveProvider`; importing the package (even `cn`) in a React Server Component no longer fails; tree-shaking works; `./tokens` includes the animation keyframes; CommonJS types resolve.
- **`cn`** keeps Wave's type-ramp classes next to a text color (`cn('text-body-1', 'text-foreground')`) and merges the `shadow-*` scale, so a consumer class replaces the conflicting class of the same variant instead of dropping an unrelated one (classes behind a different variant, such as the gated hover colors, are kept; see Button under [Styles](#styles)).
- **Forms**: no internal button submits an enclosing form (`type="button"` everywhere); Field labels, hints, errors and consumer `aria-label`s reach the focusable element of composite controls; Field keeps a child's own ids; RadioGroup finds items inside Fragments and wrappers; value controls participate in native forms.
- **Inputs**: SpinButton accepts typed negatives, decimals and multi-digit values, rounds decimal steps (`0.1 + 0.2` is `0.3`), supports the APG keys and keeps focus on the input; SearchBox keeps focus after clearing; 24×24px minimum targets for SearchBox clear, Rating stars, DatePicker and TimePicker buttons and SplitButton's chevron.
- **Pickers**: a DatePicker, TimePicker, Combobox, TagPicker or Dropdown created with `defaultOpen` while disabled or read-only starts closed and no longer calls `onOpenChange(false)` on mount. Combobox and Dropdown handle options inside `OptionGroup`, commit the highlighted option, skip disabled options, scroll the active option into view and expose it with `aria-activedescendant`; Dropdown supports ArrowUp, Home/End and typeahead; the listboxes no longer close while the input has focus; ColorPicker opacity, preview and emitted value agree, and the selected preset and swatch are visible on any color; switching Combobox, TagPicker, DatePicker or TimePicker to `readOnly` or `disabled` while typing drops the typed text.
- **Dates and times**: DatePicker's default format and parse round-trip and blur no longer rewrites an unedited date; the calendar closes on Escape and outside presses, is a labelled dialog with keyboard navigation from the focused day (Space, Home/End, Shift+PageUp/PageDown, RTL), clamps month changes to the month's last day, opens on a month inside `minDate`/`maxDate`, and localizes month and weekday names; TimePicker validates `step`, `minTime` and `maxTime` (a `step` of 0 no longer hangs the page) and displays off-grid values in the chosen format. A DatePicker or TimePicker rendered on the server with `defaultOpen` (or `open`) is closed in the server HTML and opens once hydrated (it reported `aria-expanded="true"` with `aria-controls`/`aria-activedescendant` pointing at missing elements). Both send `autoCapitalize` and `autoCorrect` to the text input (they landed on the wrapper `<div>`).
- **Overlays**: Escape and outside presses close only the topmost overlay; focus traps skip disabled, hidden and `tabindex="-1"` elements; closing returns focus to the element that opened the overlay, or to a trigger when that element is gone or nothing had focus (also after unmounting while open); stacked overlays share the scroll lock; Dialog is responsive (max width and height, scrolling body); unnamed dialogs warn in development; `Dialog.Footer` warns when rendered outside `Dialog.Content`; Popover's external toggles work; a Dialog opened from `Popover.Content` stays open; popups flip and shift at the viewport edges and are no longer clipped by scroll containers. An `autoFocus` element keeps focus in a surface opened above or inside another open Dialog or Drawer (a confirm Dialog over a Drawer, a Dialog nested in another Dialog's content, a `Popover.Content` with an `autoFocus` field opened from a Dialog); the outer trap pulled focus back to the new surface's first element or to the popover trigger. Tab and Shift+Tab inside a consumer `<Portal>` rendered in a Dialog or Drawer (or in a popover opened from one) move between the portal's elements and wrap to the dialog's last and first element at the portal's edges (every Tab jumped to the dialog's first element). A focus trap no longer fights another script (another focus-trap library) that moves focus out again while the trap returns it; it recursed until a stack overflow. Closing the last Dialog or Drawer restores an inline `overflow-x`/`overflow-y` on `<html>` (such as `overflow-y: scroll` for a stable scrollbar) with its priority. A trigger click that the parent of a controlled modal rejected no longer decides where focus returns after a later open that no trigger started. The development warning for a Drawer that cannot open runs a second after mount against the latest render, so a trigger in a conditional Fragment that appears right after mount no longer causes it; it reads "Drawer has no way to open: …". Inside a Dialog (or any focus trap), Tab and Shift+Tab from an open InfoLabel button, or from a control whose Tooltip is showing, placed in a `<Portal>` or in a Popover opened from the dialog, move to the next or previous element (focus stayed on the InfoLabel button until Escape, or jumped to the dialog's first element); leaving a popover whose trigger sits in a `<Portal>` goes to the element after the trigger. A focus trap returns focus inside when focus went to an outside element that was then removed or blurred (focus stayed on `<body>`). Like DatePicker, TimePicker and TagPicker, a Popover, Dialog, Drawer or popup Menu rendered on the server with `defaultOpen` (or `open`) is closed in the server HTML and opens once hydrated, without an `onOpenChange` call; its trigger reported `aria-expanded="true"` (Popover, Drawer and Menu also an `aria-controls`) for a surface that was not in the HTML.

The "Select all rows" checkbox stays mixed after a click that leaves the selection partial (a controlled parent that filters or ignores the change); it showed and reported "not checked". Cells inside a Fragment name the row's selection control. A `<caption>` inside a Fragment stays the first child of a DataGrid with `columns`, and names a Table's scroll region. The "Select row" fallback warning now reads "no child is a `DataGrid.Cell`, `<td>` or `<th>` element…".
- **Server Components**: compound parts written in a React Server Component reach the client as lazy references, and every compound now recognises them, so the server HTML and the client behaviour are the same as in a client file: Accordion items, triggers and panels (the value became the button label), AvatarGroup members (listed by name in the overflow popup), Carousel slides (an empty `<div>` rendered), `Option`/`OptionGroup` in Combobox and Dropdown (the selected label was missing until hydration), DataGrid parts (a `DataGrid.Header` child suppresses the header from `columns`, and row selection controls are named after the first `DataGrid.Cell`), `Drawer.Trigger`/`Close`/`Title` (the trigger became hidden panel content), List items (grid semantics on the server), `Menu.Trigger`/`Menu.Popover` (a static `role="menu"` rendered around them), Nav items and categories (the category holding the current value stayed collapsed), TabList tabs and panels, and nested `Tree.Item`s. A Wave `Button` passed from a Server Component as MessageBar `dismiss`, SearchBox `dismiss` or Tag `dismissIcon` is merged into the built-in button instead of nested inside it.
- **Dismiss and clear slots** (Tag `dismissIcon`, MessageBar `dismiss`, SearchBox `dismiss`), one rule for all three: a slot object wraps the default icon only when its element is an intrinsic, non-void tag without `dangerouslySetInnerHTML` whose children render nothing. A slot object with a component `as` (`{ as: CloseIcon, className: 'text-error' }`) no longer gets the default icon as children (icon components that render their children drew two glyphs), `{ as: 'img', src, alt: '' }` renders the image as the icon, and `dangerouslySetInnerHTML` on a slot object, on the deprecated button-object form or on a merged `<button>`/`Button` renders its markup inside the built-in button (it threw "Can only set one of `children` or `props.dangerouslySetInnerHTML`"). Before, the presence check consumed the generator and the content rendered empty, or React logged "Using Iterators as children is unsupported".
